1) MATERIAL RECEIPTS MUST UPDATE STOCK (Not just add rows)

Problem now

Material receipts only add a row. The received quantity is not added to existing stock totals, and total quantity per material is not shown. Also CFT UOM is missing.

Required fix
	1.	Implement a true Stock Ledger:
	•	Every receipt creates a +quantity ledger entry.
	•	Every consumption creates a -quantity ledger entry.
	•	Stock balance is always derived from ledger totals (no manual balances).
	2.	Add UOM options (must include):
	•	CFT, Ton/MT, Cum, Liters, Kgs, Barrels (Emulsion), Nos
	3.	Since mix consumption is calculated by weight/tons, implement UOM conversion rules:
	•	For each aggregate material, store a “conversion factor”:
	•	Example: 1 CFT = X tons (or X kg), configurable per material.
	•	Allow admin to set/modify conversion factor in Material Master.
	4.	In Material Receipt entry, include:
	•	Date/time
	•	Supplier Name
	•	Vehicle No
	•	Challan/Receipt/Invoice No
	•	Material, Qty, UOM
	•	Stock Owner: Party/Job OR Common/HLC (who supplied it)
	5.	Receipt must update:
	•	Party stock bucket OR HLC/common stock bucket
	•	Material-wise running balance must be visible.

3) TRUCK DISPATCH MUST AUTO-CALCULATE CONSUMPTION (AGG + BITUMEN + LDO) AND UPDATE STOCK

Problems now
	•	Aggregate consumption not calculated (no template).
	•	Bitumen not calculated or deducted.
	•	LDO not deducted.
	•	No tracking of who supplied bitumen/LDO (party vs HLC/common).

Required behavior

When a Dispatch/Load entry is saved (per truck/load):
Fields:
	•	Date/time
	•	Job/Party
	•	Truck No
	•	Mix Type + Select Mix Template
	•	Load weight in Tons/MT (for Phase 1)

System must auto-calculate theoretical consumption:
	•	Aggregate consumption per size (tons) from template
	•	Bitumen consumption (tons) from bitumen %
	•	LDO consumption (liters) from LDO norm × tons

Stock deduction logic (must be correct)

For each material consumed (aggregates, bitumen, LDO):
	1.	Deduct from that Party stock if the Party is the supplier of that material
	2.	Else deduct from HLC/Common stock
	3.	If insufficient stock → show shortage warning and do not silently allow negative balances.
	4.	Each deduction must create a -ledger entry and update running balances immediately.

Supplier ownership must be tracked

For each receipt and each stock item we must know:
	•	Which party supplied it OR HLC/common procured it.

So the dispatch must correctly reduce:
	•	Giridhar-supplied bitumen → Giridhar bitumen stock
	•	HLC-procured bitumen → HLC bitumen stock
Same for LDO.

4) EQUIPMENT USAGE / DIESEL LOG MUST TREAT “ISSUED” AS BALANCE, NOT CONSUMPTION

Problem now

The system treats “diesel issued” as “diesel consumed”, which is wrong.

Required fix

For equipment logs (plant/site equipment):
	•	Capture meter type:
	•	Hour meter for JCB/Loader/Generators etc.
	•	Odometer for trucks/tippers/tractors
	•	Capture opening and closing readings → compute hours/km

Fuel logic must show separately:
	•	Diesel Issued (added)
	•	Diesel Consumed (computed)
	•	Diesel Balance (remaining)

Consumption calculation:
	•	Default: Consumed = hours × norm (L/hr) OR km × norm
	•	Balance = opening balance + issued − consumed
(You can store “opening balance” per equipment/day OR infer from previous day close)

At minimum, in the report/dashboards:
	•	Do not label issued fuel as consumed.
	•	Consumption must be computed, balance must be shown.
