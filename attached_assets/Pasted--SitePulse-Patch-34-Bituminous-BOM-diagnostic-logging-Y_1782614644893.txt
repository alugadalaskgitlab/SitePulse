You confirmed the DBM/BC items are linked to the correct, fully-filled mix template (with
20/10/12/6/dust + bitumen% + grade), yet only the bitumen row reaches the BOM. The derivation

engine receives — so we can see whether the aggregate components arrive with `percent = null/0`
(or get dropped) for these items.

## How to use
1. Apply, rebuild/restart.
2. Open the **BOM / Work Demand** page for the project (this calls the endpoint).
3. In Replit's **server console / logs**, copy the `[BITUMEN BOM]` blocks for your DBM/BC items
   and paste them back to me.

What I'll be looking for:
- `resolvedTemplate.components` → are the aggregate rows present, and is `percent` a number or
  `null`? (If `null`/0 → the proportions aren't reaching the engine → I fix the read/mapping.)
- `componentCount: 0` or `"NO TEMPLATE RESOLVED"` → the item is hitting the wrong/empty template
  → it's a template-resolution bug (I fix the resolver).
- `derivedRows` lists only bitumen → confirms aggregates are skipped at derivation.

This one log will tell us exactly which of the three it is, and I'll ship the precise fix.
