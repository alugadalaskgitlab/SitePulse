INSTRUCTION 06G-HF — FIX GUIDED DPR WHITE SCREEN AFTER BOQ ITEM SELECTION

This is an URGENT, extremely narrow runtime hotfix.

Do NOT change any DPR workflow, arrangement resolution, material receipt
logic, wizard flow, schema, or calculations.

ROOT CAUSE CONFIRMED IN CURRENT REPO

File:
client/src/components/ActivityReceiptStrip.tsx

`ActivityReceiptStrip` correctly passes:

dailyMaterialName={dailyFulfilment?.materialName ?? null}

to `RecordReceiptDialog`.

The `RecordReceiptDialog` props TYPE also declares:

dailyMaterialName: string | null

BUT the function parameter destructuring currently omits
`dailyMaterialName`.

It currently starts conceptually as:

function RecordReceiptDialog({
  open,
  onOpenChange,
  props,
  arrangement,
  dailyOverride,
  received,
  uploadFile,
  toast,
  testIdPrefix
}: { ... dailyMaterialName: string | null ... })

Inside the component, `dailyMaterialName` is then referenced in the render
and mutation payload.

This causes:

ReferenceError: dailyMaterialName is not defined

as soon as an ActivityReceiptStrip mounts after selecting a BOQ item,
blanking the whole Guided DPR page.

FIX

Add `dailyMaterialName` to the RecordReceiptDialog function destructuring.

Nothing else.

Expected corrected parameter conceptually:

function RecordReceiptDialog({
  open,
  onOpenChange,
  props,
  arrangement,
  dailyOverride,
  dailyMaterialName,
  received,
  uploadFile,
  toast,
  testIdPrefix
}: { ... })

Then verify both usages work:

- display:
  arrangement?.materialLabel || dailyMaterialName

- receipt create payload:
  material: arrangement?.materialLabel || dailyMaterialName || ""

DO NOT replace or rewrite ActivityReceiptStrip.
