What I confirmed, in plain terms

Safeguard #2 (search everywhere stock is calculated) just caught a real, pre-existing bug — separate from cancellation entirely. There are actually two different places in this app that calculate Store Items stock, and they don't agree with each other:

The correct one (used on the Stores Hub dashboard) properly leaves out draft GRNs that haven't been finalized yet.
A second, different one — used specifically on the Purchase Indents verification screen, where a Stores person checks "do we actually have enough of this to approve the indent" — does not leave out drafts. It counts a draft GRN (something not yet confirmed as actually received) as if it were real, in-hand stock.

That means, right now, a Stores person could see an inflated "available" number while verifying an indent and approve it thinking there's enough material, when part of what's being counted hasn't actually arrived yet. This is exactly the kind of thing Krishna's caution was pointing at, and it's real — worth fixing regardless of the cancellation work.

Safeguard #3 (check linked records before cancelling) is also concretely real. I found two genuine links:

An Issue Voucher can be tied to an Internal Requisition (IRN) it was created to fulfill.
A GRN item can be tied to a Purchase Indent it was received against.

If either gets cancelled without checking this, the requisition or indent it was linked to could be left silently showing "fulfilled" or "received" when it actually wasn't — a real, financially-relevant gap Krishna was right to flag.

Batch 8 (final): Replace GRN/Issue Voucher delete with a proper, safe Cancel

This applies to the Store Items system (store_grns/store_issues) — not Plant Bulk Materials, which already has cancellation handled separately.

Add cancellation fields: isCancelled, cancelledAt, cancelledBy, cancellationReason on both store_grns and store_issues, using the same shared pattern already used elsewhere in the app. Migrate existing rows to isCancelled = false, applied safely to both dev and production.
Replace the delete endpoints — remove DELETE /api/stores/grns/:id and DELETE /api/stores/issues/:id entirely (don't leave them active as a hidden back door). Add POST /api/stores/grns/:id/cancel and POST /api/stores/issues/:id/cancel instead, each requiring a cancellation reason, using the same permission currently required for delete.
Fix every place stock gets calculated, not just one. This specifically includes the known second calculation (getStoreItemsWithBalance, used by the Purchase Indents verification screen at /api/stores/stock-balance), which currently wrongly includes drafts and needs the same draft-and-cancelled exclusion as the main Stores Hub summary. Please also search for and fix any other dropdown, report, or export anywhere in Store Items that shows a quantity or balance, so all of them consistently leave out drafts and cancelled records.
Check linked records before allowing cancellation:
If a GRN item is linked to a Purchase Indent (indentItemId), cancelling it should also correctly update that indent's received-quantity status rather than leaving it silently wrong.
If an Issue Voucher is linked to an Internal Requisition (irnId), cancelling it should also correctly revert that requisition's fulfilled status.
If cancelling would leave any such linked record in an inconsistent state, block the cancellation with a clear message rather than doing it silently.
History and safety: cancelled records stay visible in a "Show Cancelled / History" view — with who cancelled it, when, and why — but excluded from active lists, dropdowns, and stock totals. No editing or re-cancelling something already cancelled. Record an audit-log entry for every cancellation.
