Instruction 06X-HF6 — Dispatched Equipment Not Discovered When Editing an
Already-Existing DPR (Send this now, do not defer to 06Y)

PRIORITY

Send this on its own, now — do not bundle with Part 3 (permission gate) or
wait for 06Y. This closes the loop on the equipment dispatch fix Sunil has
been testing for several days: the crash is fixed (06X-HF5), but the
dispatched machine's details still never reach the DPR that's supposed to
complete it, because of the specific gap below.

REPRODUCED SCENARIO

Site TAKKADPALLY-SIRUR already had a submitted DPR for 08 Aug 2026 before
the Soil Compactor (TS08JG4572) was dispatched to it. Opening that
existing DPR via "Edit Report" (client/src/pages/SiteEdit.tsx) shows the
compactor in the Equipment Log by name/owner, but Opening Reading, Start
Time, and Diesel Source/Issued are all blank — none of the dispatch
details came across.

CONFIRMED IN CODE

GuidedDpr.tsx and SiteEntry.tsx both discover dispatched equipment via:

  GET /api/plant-module/equipment-usage/open-today?date=<date>&site=<site>

and pre-fill opening reading/time/diesel from the result, linking via
plantUsageId so Final Submit can close the original equipment_usage row
(see GuidedDpr.tsx ~line 369-420, "Batch 05: Equipment & Fleet linkage").

client/src/pages/SiteEdit.tsx — the screen used to edit a DPR that already
exists — has NO equivalent call anywhere in the file. This is confirmed by
grep: SiteEdit.tsx never references "open-today" or the discovery query at
all. That is the entire root cause. It is not a data problem and not
something wrong with the dispatch itself — the screen simply never asks.

REQUIRED FIX

Add the SAME discovery mechanism already used by GuidedDpr.tsx/
SiteEntry.tsx to SiteEdit.tsx — reuse the existing query, the existing
plantUsageId linkage, and the existing close-on-submit logic. Do not build
a second/parallel discovery mechanism.

1. On load, SiteEdit.tsx must call the same
   GET /api/plant-module/equipment-usage/open-today?date=<dpr date>&site=<dpr site>
   query GuidedDpr.tsx already uses.
2. Any open dispatch returned that is not already represented by a row in
   this DPR's Equipment Log must be offered the same way GuidedDpr.tsx
   offers it — pre-filled opening reading, start time, diesel source and
   issued quantity, machine, and hire info — ready for the user to enter
   the closing reading/time and complete it.
3. Saving/submitting this edit must close the original equipment_usage
   row via the SAME mechanism already used elsewhere (closePlantUsage /
   equivalent), preserving its id, setting closedByUserId/closedByDprId/
   closedAt correctly — never creating a second, duplicate equipment_usage
   row for the same dispatch.
4. If the DPR is later re-edited again after this dispatch was already
   closed through it, the now-closed record must not be re-offered as an
   open dispatch a second time.

B. Completing it from Edit Report (entering closing reading and saving)

C. A DPR created fresh via Guided/Detailed entry with a pending dispatch

D. Re-opening the DPR again after the dispatch was already closed through

E. Full test suite.
