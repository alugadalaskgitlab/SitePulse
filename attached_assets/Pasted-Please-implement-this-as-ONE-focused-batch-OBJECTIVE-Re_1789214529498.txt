4. PERIOD CALCULATIONS

For the selected date range:

Opening Meter
= first valid log's opening meter (`openingReading`) in that period

Closing Meter
= last valid log's closing meter (`closingReading`) in that period

Working Hours
= total actual working/meter hours recorded for that equipment in the period

Clock Duration
= sum of each usage log's Start Time → End Time duration

Do NOT calculate Clock Duration as elapsed calendar time between first and last date.

If any included usage record lacks a valid Start/End duration (the existing
calculateEquipmentClockDuration() already correctly returns null rather than
0 for a missing/malformed pair — do not lose that distinction when summing
across the period), do not silently count that record as zero when totaling
the period figure. Show the period Clock Duration as partial/incomplete, or
otherwise visibly indicate that some duration data is missing, rather than
presenting a neat-looking but understated total.

Diesel Issued
= total diesel added/issued to that equipment during the selected period

Opening Tank
= opening tank balance from the first valid equipment log in the period

Closing Tank
= closing tank balance from the last valid equipment log in the period

Diesel Consumed
= Opening Tank + Diesel Issued - Closing Tank

IMPORTANT:
Only calculate Diesel Consumed when the required first Opening Tank and last
Closing Tank are reliably available.

Use the existing tank-measured reliability rule, exactly as already coded in
resolveDieselPerformance() (shared/equipmentPerformance.ts): a reading only
counts as reliable when `dieselBalanceConfirmed === true` on that record AND
opening, closing, and issued are all valid non-negative finite numbers AND
the computed (opening + issued - closing) is >= 0 — this is what the
existing code labels basis "tank_measured", as opposed to "issued_only" or
"unavailable". For the period-level figure, BOTH the first applicable
boundary record's opening reading AND the last applicable boundary record's
closing reading must individually satisfy this same reliability rule.

If either boundary record fails this check:
show "Incomplete" or "—".
Do not invent a value. Do not substitute Diesel Issued into this cell as if
it were consumption — Diesel Issued stays visible in its own column
regardless, but the Diesel Consumed cell itself must read Incomplete/— when
the tank data doesn't support a real figure.

Expected Diesel
= existing equipment consumption norm applied to actual activity using the
existing correct norm logic (already unit-aware per machine — hour-meter
machines use L/hr, odometer machines use L/km, trip-based entries convert
accordingly; do not rewrite this, reuse it as-is).

Difference
= Actual Diesel Consumed - Expected Diesel

Show this as litres, e.g.:

+12 L
-8 L

Do NOT show percentage variance.

If Diesel Consumed is Incomplete/—, Difference must also show Incomplete/—
rather than being computed against Expected Diesel from a missing actual
figure.

Consumption Rate
= actual consumption in the machine's existing canonical norm unit only:
L/hr for hour-meter equipment, or L/km for odometer/trip-distance equipment
(trip-based activity is already converted to an L/km-equivalent by the
existing norm logic — do not invent a separate L/trip unit; no such unit
exists anywhere in this codebase today and none should be created).

Do not combine incompatible units.

If Diesel Consumed is Incomplete/—, Consumption Rate must ALSO show
Incomplete/— — do not fall back to calculating a rate from Diesel Issued
instead of true consumption. The rate must only ever be computed from a real
Diesel Consumed figure, never from Diesel Issued.
