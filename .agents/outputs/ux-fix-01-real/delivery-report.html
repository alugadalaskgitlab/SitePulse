UX-FIX-01 delivery report

Implemented on top of accepted BOQ-LINK-01. Neither batch has been published. Production was not modified. The companion “Signed-in development verification” report contains embedded desktop/mobile screenshots for A–J and the API/database evidence summary.

Two deliberate mandatory-rule changes

  1. Labour: before, a category-default-only row triggered a missing-count error; now untouched rows are ignored and new blank rows are omitted from save payloads. Count, Hours, Task, Contractor or worker-name evidence makes a row filled. A filled row without Count gives “Enter the number of workers”. Invalid counts remain invalid. Saved identities are retained.
  2. Breakdown: before, DPR Breakdown did not require a daily status reason; now a Breakdown row being saved requires “Enter the breakdown reason”. The existing Idle — No Work rule and all other statuses are unchanged. The new rule is DPR-entry/write-only, not a read gate or a standalone plant-usage rule. Historical rows are not rewritten.

The mandatory-parity baseline was adjusted only for these two approved differences. Start/end pairing and all operational calculations remain unchanged.
