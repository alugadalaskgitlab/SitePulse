PART 3 — DIESEL STANDALONE RECEIPT CONTROL
Today, a Diesel Material Receipt can be created without being linked to any
Daily Diesel Requirement purchase, and without any server-side check against
how much of that purchase is still outstanding. Fix this as follows, for
Diesel only:

1. When a user starts a new Diesel Material Receipt and there is at least one
   approved Daily Diesel Requirement purchase with outstanding (not fully
   received) quantity, the normal path must require them to select that
   requirement/purchase — same as the existing "Record Receipt" flow already
   launched from the Diesel Requirement screen. Do not let an ordinary user
   silently create an unlinked Diesel receipt when a matching outstanding
   purchase exists.
2. Add a genuine PM/Admin-only exceptional path: "Record Exceptional Standalone
   Diesel Receipt", for real cases where no Diesel Requirement exists yet
   (emergency purchase before a requirement was raised, an opening/legacy
   correction, diesel received from another site/company, or similar). This
   requires a mandatory reason and is only available to PM/Admin (or Owner).
3. Any receipt created through that exceptional path must be visibly flagged
   as pending regularisation — reuse the existing amber "regularise this
   receipt" notice pattern already used elsewhere in Material Receipts (the
   same visual language as the current "No approved indent linked — regularise
   this receipt through its Edit action" notice), adapted to say something
   like: "Exceptional standalone diesel receipt — link this to a Daily Diesel
   Requirement to regularise." It must stay visibly flagged until it is linked
   to a Diesel Requirement (existing or newly raised to cover it) via Edit.
   Once linked, the flag clears and it behaves like a normal diesel receipt
   from then on.
4. Server-side enforcement (not just UI):
   - A linked diesel receipt cannot be created/saved for more than the
     remaining outstanding quantity of its Diesel Requirement purchase; once a
     purchase is fully received, reject any further linked receipt against it.
   - An ordinary (non PM/Admin) user's attempt to save a standalone Diesel
     receipt with no linkedDieselRequirementId, while an outstanding purchase
     exists, must be rejected server-side with a clear message pointing them to
     the correct requirement(s) to select from — not just hidden in the UI.
   - A PM/Admin exceptional standalone diesel receipt is allowed only with a
     reason present, and is saved with the pending-regularisation flag set.
5. Do not change anything about standalone receipts for non-diesel materials.
