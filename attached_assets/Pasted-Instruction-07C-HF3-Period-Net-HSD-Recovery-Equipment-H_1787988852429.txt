PART 1 — CORRECT HSD RECOVERY TO PERIOD-NET BASIS

CURRENT ISSUE

The present HSD pricing logic sums only each day's positive excess:
daily excess = max(0, actual - expected)
and ignores days where actual diesel is below expected.
This can overstate vendor recovery.

For equipment hire billing, diesel consumption must be reviewed over the selected Hire Group / billing period.
This is especially important because daily figures can vary due to:
- operating load and site conditions;
- idling;
- timing of refuelling;
- opening/closing fuel balance;
- practical tank-level measurement differences;
- diesel issued on one day but effectively consumed across more than one operating day.

Therefore a low-consumption day must be allowed to offset a high-consumption day within the SAME hire billing period.

REQUIRED CALCULATION

For each Hire Group:

TOTAL ACTUAL HSD
= sum of reliable actual HSD issued/consumed records for the group period

TOTAL EXPECTED HSD
= sum of expected diesel generated from the existing consumption norm and valid operational activity

NET EXCESS HSD
= max(0, Total Actual HSD - Total Expected HSD)

Suggested recovery must be based on NET EXCESS HSD.
Do NOT calculate the final bill recovery by summing only positive daily excess values.

EXAMPLE

Total Actual HSD = 41.12 L
Total Expected HSD = 30.00 L
Correct Net Excess = 11.12 L
NOT 22.25 L merely because individual over-consumption days total 22.25 L while under-consumption days were ignored.

PART 3 — APPLICABLE HSD RATE FOR PERIOD-NET EXCESS

HF2 already established the historical rate lookup:
- same-day diesel purchase rate where available;
- otherwise latest valid rate BEFORE that date;
- never use a future purchase rate;
- multiple purchases on the same applicable date use quantity-weighted average;
- no valid rate -> "Rate unavailable".

Retain that historical-rate discipline.

EXACT WEIGHTING METHOD (tightened — implement precisely this way, do not improvise)

Because Net Excess is now a single period figure with no specific day(s)
attached to it, the rate lookup can no longer be triggered only on days
where that day's own excess was positive. Instead:

1. For every date in the Hire Group period that has actual diesel > 0
   (regardless of whether that specific day was over or under its own
   expected figure), resolve that day's applicable historical rate using
   the same same-day-or-latest-prior rule (never a future purchase; same
   day multiple purchases use quantity-weighted average, exactly as
   today's per-day logic already does).
2. Compute the period's Applicable Weighted HSD Rate as the
   quantity-weighted average of those per-day rates, weighted by each
   day's ACTUAL diesel litres (not by excess litres, since excess is no
   longer a per-day concept):
   weighted rate = sum(day.actualDiesel x day.resolvedRate over days with
   a resolved rate) / sum(day.actualDiesel over those same days)
3. If NO day in the period with actual diesel > 0 has a resolvable rate,
   the whole period's rate is "Rate unavailable."
4. If only SOME days have a resolvable rate, use only those days'
   actualDiesel/rate pairs in the weighted average (do not fail the whole
   period for a partial gap), but report in your response which dates, if
   any, lacked a resolvable rate.

Show clearly:
Actual HSD: ___ L
Expected HSD: ___ L
Net Excess: ___ L
Applicable Weighted HSD Rate: Rs ___ / L
Suggested Recovery: Rs ___

Suggested Recovery
= Net Excess HSD x Applicable Weighted HSD Rate

If there is only one applicable historical rate for the period, naturally use that rate.
If no reliable valid historical rate can be established, show:
Rate unavailable
and allow authorised user to enter a manual recovery rate/amount.
Do not guess.
