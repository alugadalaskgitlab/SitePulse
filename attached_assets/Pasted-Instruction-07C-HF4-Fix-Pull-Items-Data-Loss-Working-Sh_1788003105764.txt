GROUND TRUTH FROM THE SCREEN RECORDING — CONFIRMED ROOT CAUSE FOR PART 2

Frame-by-frame review of the recording shows the following exact sequence
on a real Vendor Bill (MAHIPAL, HLC/VB/2026/0045, 19-Jul-2026 to
31-Jul-2026):

1. A Tractor Dozer Monthly Hire Group is added. The app correctly removes
   13 stale raw activity lines and computes Gross Rs 25,161.29, HSD Net
   Excess 11.12 L, Suggested Recovery Rs 1,163.15. Accepting the recovery
   correctly produces ONE clean line item: "TRACTOR DOZER · 19-JUL-2026-
   31-JUL-2026 · MONTHLY HIRE", amount Rs 23,998.14. The line items table
   TOTAL correctly reads Rs 23,998.14. This part is confirmed working —
   do not change this calculation path.

2. The blue banner reads "PULL 2 OTHER ITEMS". The user clicks it.

3. In the very next captured frame, a toast reads "0 items auto-populated
   from records" and the line items table is now EMPTY — TOTAL Rs 0.00.
   The Rs 23,998.14 hire-group line is GONE, not just un-incremented.

This is not primarily a count-display mismatch (banner says 2, only 0
inserted). The confirmed, observable defect is that clicking Pull Items
REPLACED the entire lineItems array with the freshly fetched auto-items
result (which happened to resolve to 0 rows) instead of ADDING eligible
rows to whatever was already in the bill. The pre-existing hire-group
line was not part of that fetch and must never be removed by it.

REQUIRED FIX (this is the priority item in this batch)

In client/src/pages/VendorBills.tsx, handleAutoPopulate (or whatever now
implements "Pull Other Items") must:
a. Never call setLineItems(newItemsOnly). It must merge: keep every
   existing line item (hire-group-derived lines, manual lines, previously
   pulled lines) and APPEND only the newly fetched eligible auto-items
   that are not already present (by source + sourceId/date, avoid
   duplicate insertion on repeated clicks).
b. The count shown on the banner ("PULL N OTHER ITEMS") must be computed
   from the exact same final eligibility list that clicking the button
   actually inserts — apply, before showing N:
   - exclude entryType monthly raw hire evidence;
   - exclude raw equipment items covered by an Equipment Hire Group
     (existing HF1 rawAutoItemCoveredByHireGroup logic);
   - exclude items already present in the current Vendor Bill's line
     items;
   - preserve legitimate Daily/Trip/unrelated auto-items.
   availableOtherItems.length must equal the number of rows
   handleAutoPopulate actually adds. If 0, show "NO OTHER BILLABLE
   ACTIVITIES AVAILABLE" (or hide/disable the button) — never show
   "Pull 2" and then add 0.
c. Investigate and report explicitly why the fetch itself returned 0
   eligible items at that moment when the banner had shown 2 seconds
   earlier — do not assume it was only the array-replacement bug; confirm
   whether the eligibility query result also changed, and if so why (e.g.
   stale client cache, a race with the hire group's own state update,
   etc). Report the actual cause found, not a guess.

Add a regression test reproducing the exact observed scenario: a bill
with an existing hire-group-derived line item (source reflecting the
group, not "auto"), where "Pull N Other Items" is then clicked. Assert
the existing hire-group line is still present and unchanged afterward,
and that exactly N new eligible rows were appended (not that the array
was replaced with N or fewer rows).

PART 3 — PRESERVE THE ORIGINAL ACTIVITY DESCRIPTION, AND KEEP IT DISTINCT
FROM THE COMPUTED "NO ACTIVITY" STATUS

CURRENT GAP (confirmed in code)

The current Working Sheet row renders the STATUS word as a hardcoded
"WORKED" whenever any activity record exists that day, with the real
recorded description (e.g. "C&G (SITE)", "EMBANKMENT WORK (SITE)", "NO
WORK (SITE)") shown only as a small secondary line underneath. That
secondary text is not the bug — losing the distinction between two very
different facts is:

- "NO WORK (SITE)" is a REAL, RECORDED DPR/usage entry — the crew logged
  that the machine was present that day with nothing assigned. It may
  still carry hours/diesel data.
- "No Activity" is the app's OWN COMPUTED status for a date with ZERO
  records of any kind.

These must never be visually or semantically merged. A day whose actual
recorded description says "NO WORK" is still a WORKED/RECORDED day (it
has a real DPR/usage row) and must be labelled and grouped as such — not
displayed or treated the same as a day the app marks "No Activity"
because nothing was logged at all. Do not relabel a recorded "NO WORK"
entry as the computed "No Activity" status, and do not let a genuinely
blank day borrow the "NO WORK" wording.

Show the real recorded description prominently (not just as small
muted secondary text) for any date that has an activity record, whatever
that description says. Status derivation remains conservative:
- maintenance breakdown log -> Vendor Breakdown
- an activity record exists (regardless of what it says, including "NO
  WORK") -> show the actual recorded description as the primary text
- no activity record and no maintenance record at all -> "No Activity"
  (informational only, distinct wording, never a deduction trigger)

A recorded "NO WORK" description must NOT automatically become a vendor
deduction. Only a confirmed vendor-caused breakdown/unavailability or an
explicit reviewer decision creates a deduction.


PART 4 — WORKING SHEET MUST SUPPORT THE BILL REVIEW, NOT BYPASS IT

For Monthly Hire the Working Sheet is evidence, not the gross-hire
quantity calculation. The reviewer must be able to see, in one place:
every date in period; which had recorded activity (with its real
description) vs none; hours/trips where available; vendor breakdown
records; HSD actual/expected/variance. Breakdown reviewer decisions made
here must reconcile to the Hire Calculation summary. Do NOT require
pulling these rows as ordinary Vendor Bill items to review them.

WORKING SHEET TOTALS — show at the bottom:
Period Days, Activity/Recorded Days, No Activity Days, Vendor Breakdown
Days/equivalents, Total Hours, Total Trips where applicable, Actual HSD,
Expected HSD, Net HSD Variance.

For Monthly Hire: No Activity Days are informational only and MUST NOT
reduce gross hire automatically.
