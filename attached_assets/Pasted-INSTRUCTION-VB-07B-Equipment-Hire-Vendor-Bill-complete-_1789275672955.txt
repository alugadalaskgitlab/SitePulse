BACKGROUND (confirmed by direct code review of the latest zip and a 6-minute recording of the actual New Vendor Bill → Equipment Hire flow)

- The vendor picker for Equipment Hire currently comes from a generic discovery endpoint (`/api/vendor-bills/discover-vendors` → `storage.discoverVendors`, server/storage.ts ~line 19191) that counts real DPR/Plant equipment-usage log ROWS per vendor inside the period and shows "N records". This is wrong for equipment hire specifically: a monthly-hire machine can have zero activity on some or all days and still be legitimately under hire and billable, so activity-count is the wrong eligibility test in both directions — it can hide a vendor whose machine simply didn't work that period, and it says nothing about whether the vendor has hired equipment at all versus just a stray DPR mention.
- The equipment-hire GST mechanism already exists in this file but is switched off for this bill type. Line 3130: `{billType !== "equipment" && <Card>...` wraps the entire Adjustments/GST card, so it never renders when `billType === "equipment"`. Inside that same (currently unreachable-for-this-case) code, there's already a `billType === "equipment"` branch (lines ~3148-3149) reading `gstRateEquipment`/`gstAmountEquipment`, but its basis (`categorySubtotals["equipment"]`, line 1335) reflects the OLDER itemized-equipment composer, not the current hire-groups straight-form composer (`data-testid="equipment-hire-straight-form"`, lines ~2600-2720), which computes its own independent `taxableAmount`/`netPayable` per hire group and never applies GST.
- HSD recovery computation already works correctly (`calculateHireDieselPricing` / `HireDieselRecoveryDecision` in shared/hireBilling.ts; the Select/Input UI at VendorBills.tsx lines ~2705-2711 gated on `equipment?.hireDieselResponsibility === "hlc"`), it just needs to be presented more clearly and consistently, and hidden entirely (not shown as blank/incomplete) when responsibility is "vendor".
- `hireDieselResponsibility` is a plain text column already storing exactly `"hlc"` or `"vendor"` (shared/schema.ts line 516). Reuse these two values directly — do not invent new ones.
- `shared/hireBilling.ts`, `planHireRegisterRows` (~lines 101-120) already implements exactly the open-ended-hire eligibility rule needed here: `(!equipment.hireStartDate || equipment.hireStartDate <= periodTo) && (!equipment.hireEndDate || equipment.hireEndDate >= periodFrom)`. Reuse/mirror this exact logic for the new equipment-hire vendor discovery below — do not write a second, slightly different version of the same date-overlap check.
- The daily consumption rate and its unit are already computed per day and carried through this exact bill pipeline: `EquipmentPerformanceDailyRow.consumptionRate` / `.consumptionRateUnit` ("L/hr" or "L/km", derived from Equipment Master's `meterType`: "hour_meter" vs "odometer" — shared/equipmentPerformance.ts lines 430-492), and these rows already flow into `BillingDailyRow.performance` via `buildBillingDailyRows` (EquipmentHireBillOutput.tsx). Nothing new needs to be computed for outcome B below — only displayed.
- There are currently two separate entry points that both populate the same `hireGroups` state: the vendor-discovery panel's own inline "Add Hire" buttons (lines ~2341, ~2357, already disabled once `hireGroups.length > 0`) and the straight-form's own "Select equipment" dropdown (`onValueChange={value => selectHireEquipment(...)}`, ~line 2610). Consolidate to one clear path (see Outcome 2) — a reviewer should not have two different ways to start the same action.

FINAL CLARIFICATIONS BEFORE BUILDING (read these alongside the Outcomes above — they refine sequencing, scope, and two places where an earlier draft of this instruction was imprecise)

1. PERMITTED SERVER SCOPE, AND WHY IT'S NEEDED
Outcome 1 necessarily requires server-side Equipment Hire vendor discovery — this cannot be done client-side only. Accordingly, server/routes.ts and server/storage.ts may also be changed, but ONLY for this dedicated Equipment Hire discovery requirement and for server-side net-payable parity (below). Do not change generic `discoverVendors` behavior for other bill types.
Net-payable parity is a real, already-confirmed risk, not a hypothetical: server/storage.ts, `updateVendorBillStatus` (~lines 15790-1861), on the "approved" transition for `billType === "equipment"` (~lines 15823-1848), freezes `netPayableAmount` by reading `vendorBillItems` rows, grouping them into `categorySubtotals`, and applying `gstRateEquipment`/etc. to that itemized subtotal — this is the OLDER itemized-composer path, not the hire-groups straight-form's own per-group Gross Hire → Breakdown Deduction → HSD Recovery → Other Debit → Advance Adjustment → Other Credit → Taxable Amount → GST → TDS sequence from Outcome 6. If a bill was built via the straight-form composer, this freeze step will not reflect the same figures shown on screen unless it is corrected to source its numbers from what the straight-form actually computed and saved for that bill, not re-derive them from `vendorBillItems`/`categorySubtotals`.
The saved/approved bill, the on-screen summary, and the PDF/Excel export must all produce the same: Taxable Amount → GST → Invoice Total → TDS → Net Payable. Whatever the straight-form computes and lets the user review must be exactly what gets persisted and frozen at approval — persist those final per-hire-group figures (or their bill-level total) at save time so the approval step can reuse them directly instead of recomputing from a different source of truth.

2. FORM DEPENDENCY / ORDER
Equipment Hire vendor eligibility depends on the selected bill period. Therefore the functional flow is:
  Bill Type = Equipment Hire → Bill Period → Vendor → Equipment → auto-filled hire terms/activity/recoveries.
Do not run or show Equipment Hire vendor discovery until a valid Period From and Period To are available. (This corrects Outcome 2's original wording, which listed Vendor before Bill Period — period must be known first for discovery to even be meaningful.)

3. HIRE DATES
A valid Hire Start Date is required for normal Equipment Hire billing. A blank Hire End Date means ACTIVE / STILL UNDER HIRE. Eligibility:
  hireStartDate <= periodTo AND (hireEndDate is blank OR hireEndDate >= periodFrom)
Do not treat a blank Hire Start Date as proof the machine was under hire for every historical period — the start date must genuinely be set and on-or-before the period end; only the END date is allowed to be blank-meaning-active.

4. CONSUMPTION UNIT — CURRENT CANONICAL MASTER ONLY
For this batch, do not invent reciprocal fuel-efficiency units. Current Equipment Master supports only: hour_meter → L/hr, odometer → L/km. Daily Activity must show "Actual Consumption | Master Norm" in that same canonical unit. Do not convert to km/L or hr/L in VB-07B — any future selectable norm-basis enhancement belongs to Equipment Master as a separate decision. (This replaces Outcome 9's earlier hedge about a possible km/L display — there is no such stored basis today.)
