FIX — build these three things as a static/prototype screen (sample data is fine, real API wiring is NOT required for this step)

PART A — Submit-readiness banner
At the top of the mockup DPR screen, show a compact banner (only when something is actually missing) listing each specific blocking item in plain language with a "Fix →" link that would jump to that field (in the mockup, the link can just scroll to/highlight the relevant section — no need to wire real navigation yet). PART B — Condensed Activity section
Each activity as a single-line collapsed summary by default: activity name + reach/chainage + recorded quantity, with a status chip (e.g. "Outcome needed" in amber, or a checkmark when complete). Tapping/clicking expands to show the full detail (side/chainage/L-W-T, physical qty, personnel, photos) only when the person wants it. For embankment/fill rows that pull from an excavation source, replace the "link this activity to an Execution Arrangement..." jargon with a plain sentence: "Material source: [Roadway excavation, Reach 2]" with a "Change" link — no mention of "Execution Arrangement" in the visible copy.

PART C — Condensed Equipment Log section
Each machine as one compact card: header row (machine, operator, hire status, working/idle chip), then a single stat grid (Meter hours, Clock duration, Diesel issued, Tank-confirm status) shown ONCE each — no separate "Usage Summary" repeating the same numbers. Opening/closing tank values and consumption shown below the grid, with a clear inline note when consumption is "Incomplete" explaining why (e.g. "tank not confirmed") rather than a bare "Incomplete" label.
