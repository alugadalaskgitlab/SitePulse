OBJECTIVE

Improve the Execution Arrangement status screen so PM/Admin does not normally
type Actual Quantity manually.

For each arrangement programme bar / reach, derive execution evidence from:

1. Valid submitted DPR progress;
2. Vendor Material Trips / Receipts linked to the arrangement / BOQ / bar;
3. CFT → Cum conversion where relevant.

Show both DPR and trip evidence clearly.

IMPORTANT:
Some historical DPRs and Material Trips were created before BOQ / programme-bar /
arrangement linkage was fully available.

The client will gradually correct those records by editing them.

Therefore all calculations/reports must automatically reflect the CURRENT valid
links after those edits. Do not snapshot today's incomplete linkage permanently.

Do NOT redesign DPR, Material Trips or Vendor Bills in this batch.
Do NOT create a new commercial quantity table.
Prefer ZERO schema change.


============================================================
PART 1 — USE CURRENT VALID SOURCE RECORDS
============================================================

Arrangement evidence must always derive from the current valid source data.

For DPR:
use only the current valid/non-superseded submitted DPR/progress records.

For Material Trips:
use the current active/non-cancelled/non-deleted trip record.

When a historical DPR or trip is later corrected:
- remove its contribution from the previously wrong/unlinked bucket;
- include it under the newly corrected BOQ / programme bar / arrangement;
- do not count both old and new linkage;
- no manual report rebuild or reclassification step should be required.

Derived reports/screens must refresh automatically from the corrected source data.


============================================================
PART 2 — DPR EXECUTED QUANTITY
============================================================

For every programme bar / reach covered by an arrangement calculate:

DPR Executed Qty

using valid submitted DPR progress matching:

- same project/site;
- same BOQ item;
- exact programmeBarId where available;
- exact earthworkArrangementId where available;
- relevant chainage/reach;
- compatible side/layer/lift where these fields apply.

Matching priority:

1. Exact programmeBarId + BOQ item.
2. Exact earthworkArrangementId + allocation to that programme bar.
3. Otherwise, same BOQ item/project with defensible chainage overlap and compatible
   geometry/layer information.

Use existing:
- shared/dprProgrammeLink.ts
- shared/dprGeometry.ts
- shared/chainageOverlap.ts
- existing submitted-progress aggregation

where appropriate.

Exclude:
- drafts;
- cancelled/deleted DPRs;
- superseded DPR versions;
- unrelated BOQ items;
- invalid/withdrawn records according to existing rules.

Do NOT assign the full DPR quantity to every overlapping programme bar.

If a DPR spans more than one bar:
use existing geometry/reach logic to allocate only the relevant quantity.

If the existing data is insufficient for a reliable split:
show:

"DPR quantity incomplete / requires review"

Do not guess.


============================================================
PART 3 — HISTORICAL DPR CORRECTIONS
============================================================

Some old DPRs have correct physical details such as chainage, width and quantity,
but incomplete or wrong BOQ / layer / programme linkage.

The client will correct them individually.

When a DPR is edited/version-corrected:

Example:
Old valid DPR contribution:
BOQ A / Bar 1 = 500 Cum

Corrected current version:
BOQ B / Bar 2 = 500 Cum

Required result:
- BOQ A / Bar 1 decreases by 500 Cum;
- BOQ B / Bar 2 increases by 500 Cum;
- total physical progress remains counted once.

Use only the current valid version.

Do not leave the superseded version contributing to reports.

Add tests for:
- wrong BOQ → corrected BOQ;
- wrong bar → corrected bar;
- incomplete layer → completed layer;
- repeated edit does not duplicate progress.


============================================================
PART 4 — VENDOR TRIP QUANTITY
============================================================

For earthwork/vendor arrangements calculate:

Vendor Trip Qty

from valid Material Trips linked to:

- same vendor / agency;
- same BOQ item / intended activity;
- same earthworkArrangementId where available;
- same programmeBarId where available;
- relevant project/site;
- relevant period/reach.

Use exact existing IDs wherever available.

Matching priority:

1. Exact earthworkArrangementId.
2. Exact BOQ item + compatible programmeBarId.
3. Vendor must match arrangement.
4. If exact linkage is missing, treat as incomplete historical data.

Do NOT use loose material-name matching to claim an authoritative match.

Cancelled/deleted trips must not count.


============================================================
PART 5 — HISTORICAL MATERIAL-TRIP CORRECTIONS
============================================================

Many older Material Trips were recorded before BOQ / arrangement / programme-bar
linkage was added.

The client will correct these gradually.

When an old trip is edited from:

Unlinked
or wrong BOQ / arrangement / bar

to the correct linkage:

- remove it from the old/unlinked aggregation;
- include it under the corrected vendor / BOQ / arrangement / programme bar;
- count that physical trip once only;
- reports update automatically.

Example:

Before edit:
Trip 123 — 3,500 CFT — no BOQ link

After edit:
Trip 123 — 3,500 CFT
Vendor Narasimulu
BOQ Embankment Borrow Earth
Arrangement A
Programme Bar 7

Required:
Trip 123 now appears automatically in that arrangement/bar total.

No separate "rebuild", "reclassify" or manual transfer action.


============================================================
PART 6 — AVOID TRIP / RECEIPT DOUBLE COUNTING
============================================================

Count the canonical Material Trip once.

If a Material Receipt represents the same physical trip:
do NOT add both trip quantity and receipt quantity.

There is currently no guaranteed immutable trip-to-receipt identity for every
historical row.

Therefore:
- use exact linkage/IDs where available;
- do not infer duplicates only from text similarity;
- for ambiguous old records show:
  "Partially linked historical data"

Challan / vehicle / supplier / quantity/date may support review but are not enough
to silently merge records unless current existing logic already proves identity.


============================================================
PART 7 — SHOW BOTH CFT AND CUM
============================================================

Original recorded quantity/UOM remains authoritative.

For earthwork trips recorded in CFT, display both:

Example:

Vendor Trips:

Do NOT create another conversion formula.

Never overwrite the original CFT value with Cum.

Where applicable retain/display:

- Original Qty
- Original UOM
- Converted Qty
- Converted UOM

DPR Executed Qty.

Trip Qty remains corroborating/vendor evidence.

If DPR quantity is unavailable/incomplete:
show the balance as incomplete/review required rather than silently substituting
Trip Qty unless existing business logic explicitly supports that.
