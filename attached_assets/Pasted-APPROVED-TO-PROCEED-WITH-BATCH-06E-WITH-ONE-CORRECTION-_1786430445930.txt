IMPORTANT CORRECTION — REQUIRED TODAY QTY

Do NOT derive "Required Today" by automatically prorating a programme bar's
plannedQty across its start/end date window.

A multi-day programme bar does not imply equal daily planned production.

Use this priority instead:

1. An arrangement/programme allocation that genuinely represents the
   applicable planned requirement for the activity/reach.

2. An existing day-specific programme quantity, if SitePulse already has one.

3. A reliable material requirement derived from the actual planned
   activity/reach/BOM where such a resolver already exists.

4. Otherwise:
   Required Today = "Not determined"

Do NOT invent:
- equal daily prorating;
- swell/shrinkage factors;
- loose-to-compacted conversion;
- material factors not already configured.

If the only available value is the programme bar's total plannedQty across
a multi-day window, show it only as programme-bar planned quantity/context,
not as "Required Today".
