BATCH 06M — DAILY DIESEL PURCHASE: BILL/QR + PAYMENT DETAILS

This is a SMALL enhancement to the EXISTING Daily Diesel Requirement
purchase action.

Do not redesign the diesel procurement workflow.

OBJECTIVE

When the Purchaser records a Diesel requirement as Purchased, add:
1. Bill / Invoice photo upload
2. QR / Payment Evidence photo upload — optional
3. If straightforward using the existing PI pattern:
   - Payment Status
   - Payment Mode
   - Paid By

Also investigate and report whether the EXISTING diesel Purchase action
already adds the purchased quantity to Diesel stock, and whether that same
stock is later reduced through:
- DPR Equipment Log
- Equipment Usage in Equipment & Fleet.

If stock is not currently connected correctly, REPORT ONLY.
Do not build a new stock workflow in this batch.

Expected schema change: NONE if existing attachment/payment infrastructure
can be reused.

--------------------------------------------------
1. EXISTING DIESEL PURCHASE ACTION
--------------------------------------------------

Locate the current flow:
Daily/Site Requirement
→ Diesel
→ Sent to Purchase
→ Purchaser records Purchased.

Do not change its existing status flow, quantity logic or approval flow.
Keep the current purchase form as it is except for the additions below.

NOTE: "Purchased" may not be a literal, separately-named status value in
the current Requirements Queue status model (the known status options are
requested/approved/arranged/available/expected/partly/not_available/
rejected/clarification — no confirmed distinct "purchased" state). It is
possible diesel purchase is currently represented via "Arranged" or
"Available" rather than a dedicated status. As part of this section, report
the EXACT current status/label value the Purchaser action actually sets for
Diesel today, so we can confirm this is really the right attachment point
before relying on it.
