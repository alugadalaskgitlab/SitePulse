BATCH 06 — PROGRESS REPORT v1
RA-STYLE ITEM-WISE, CHAINAGE-WISE & DATE-WISE DPR ROLLUP

This is a READ-ONLY reporting batch.

Build one new Progress Report under:

Reports Hub → Site Reports → Progress Report

The report must use submitted DPR actuals only and behave like a DPR-based measurement register / RA-bill measurement sheet.

Do NOT start:
- Tomorrow's Programme workflow changes
- Geometry/Earthwork integration
- programme-bar quantity changes
- RA billing write-back
- profitability
- Project Scope changes

No schema change is expected.

--------------------------------------------------
OBJECTIVE
--------------------------------------------------

Provide one Progress Report screen with three views:

1. ITEM-WISE
2. CHAINAGE-WISE
3. DATE-WISE

The primary use case is:

"What work has actually been recorded through submitted DPRs, where was it done, when was it done, how much has been credited against the BOQ, and what is the balance?"

The Item-wise view should feel like an RA bill / measurement-book register:

- Contract BOQ Qty
- Previous cumulative
- This-period quantity
- Cumulative to date
- Balance
- % complete
- every individual DPR measurement row underneath

This report is an AUDIT tool.

Do not silently correct or rewrite historical DPR records merely to make the report look cleaner.

--------------------------------------------------
3. CONTRACT BOQ QTY IS THE PRIMARY DENOMINATOR
--------------------------------------------------

For this RA-style report, use the raw Contract BOQ Qty as the primary quantity basis.

Show:

Contract BOQ Qty
Previous cumulative
This period
Cumulative executed
Balance
% Complete

Do NOT use `getItemScopeQuantity()` or eligible/applicable scope quantity as a silent replacement for Contract BOQ Qty.

Reason:

This is a contractual / RA-style progress report.

Scope/eligible quantity may later be shown separately as informational data, but it must not redefine:

- BOQ Qty
- Balance
- % Complete

in v1.

Formula:

Balance =
Contract BOQ Qty - Cumulative BOQ-credit Qty

% Complete =
Cumulative BOQ-credit Qty / Contract BOQ Qty × 100

Handle zero/null BOQ Qty safely.

--------------------------------------------------
4. PHYSICAL MEASUREMENT VS BOQ-CREDITED QTY
--------------------------------------------------

Reuse Batch 04 quantity semantics.

Do NOT implement a new conversion engine inside the report.

Use existing shared logic from `shared/dprGeometry.ts`, including:

- calculateDprQuantity
- quantitiesMatch
- dprConversionFactor
- dprMeasurementMethod
- existing UoM normalization/formatting

The report must distinguish:

A. physical/site measurement

from

B. BOQ-credited quantity

ONLY where they genuinely differ.

Example:

Clearing & Grubbing

150 m × 1.5 m
Physical = 225 SQM

BOQ UoM = Ha
Factor = 0.0001

BOQ-credit Qty = 0.0225 Ha

Display both:

Measured Qty: 225 SQM
BOQ Qty: 0.0225 Ha

But for:

WMM
Physical = 126 Cum
BOQ = 126 Cum

do NOT show two identical quantity columns unnecessarily.

Rule:

- same physical and BOQ quantity/unit → one Qty column
- different unit/value → show Measured Qty + BOQ Qty

Never invent compaction, loose-volume, density, tonnage, or other conversions.

Any conversion must come from existing BOQ/DPR configuration.

--------------------------------------------------
9. RUNNING CUMULATIVE — CRITICAL RULE
--------------------------------------------------

The running cumulative must be computed CHRONOLOGICALLY.

This is mandatory.

Conceptually:

1. obtain all valid progress rows
2. order chronologically using:
   - DPR date
   - stable secondary identifier/timestamp
3. calculate running BOQ-credit cumulative
4. attach that cumulative to each row
5. ONLY AFTER THAT may the UI apply a display sort

The cumulative value must NOT change simply because the user switches visual sort.

DO NOT:

sort by chainage first
→ then calculate cumulative

That would produce a false running total.

Display sort and cumulative chronology are separate concepts.

12. PREVIOUS / THIS PERIOD / CUMULATIVE
--------------------------------------------------

For selected report From/To dates:

Previous Qty =

This Period Qty =
valid submitted DPR BOQ-credit qty within From Date–To Date

Cumulative Qty =

Contract BOQ Qty - Cumulative

Previous = 0.
