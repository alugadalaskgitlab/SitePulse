BATCH 05 — RESTORE GUIDED DPR DAILY WORKFLOW, DRAFT COMPLETION & EQUIPMENT-USAGE LINKING

This is the next priority LIVE FIELD hotfix.

Batch 04 is complete.

Do NOT start any follow-up reporting, programme-bar quantity, Tomorrow's Programme, or Geometry work in this batch.

CURRENT LIVE PROBLEMS

1. The normal daily Guided DPR journey is fragmented.

From Field Home:
- "Start Today's Site Work" can enter Guided DPR;
- but once a draft exists, "Complete Today's DPR" routes to Detailed/Edit DPR instead of reopening the same Guided draft.

Current code confirms repeated hard-coded `/site/edit/:id?draft` routes in FieldHome.

Guided DPR already supports reopening a server draft through `?draftId=`.

2. Earlier DPR behaviour allowed:

MORNING:
- select activity;
- enter opening chainage;
- select equipment;
- enter opening reading/start time;
- Save Draft.

EVENING:
- dashboard clearly shows that today's DPR still needs completion;
- reopen SAME DPR;
- enter closing chainage/quantity;
- enter closing equipment reading/end time/task/etc.;
- Final Submit.

That behavioural model must be restored.

3. Current Field Home completion indicators are too shallow.

For example:
- equipment row exists → "Equipment closing meter" marked done;
- progress row exists → "Activity quantities entered" marked done.

Existence is not completion.

The repo already contains more accurate `eqClosed` / `eqOpen` style calculations elsewhere in FieldHome. Reuse/centralise existing logic rather than inventing a new completeness model.

4. Guided DPR currently has no awareness of standalone Equipment & Fleet usage, while Detailed DPR already has working `openPlantMap` / `plantUsageId` linking logic.

Therefore an Engineer can currently:
- record JCB usage in Equipment & Fleet;
- later enter JCB independently in Guided DPR;
- fail to establish `closedByDprId`;
- create genuine duplicate-count risk.

5. Guided and Detailed each maintain independent local-autosave silos.

Switching between the two can leave both:
- `guided-dpr-new`
- `site-entry-new`

local autosaves behind.

This can produce repeated "Unsaved draft found" prompts even when a real server draft already exists.

6. The "Detailed DPR" action inside Guided currently also changes the user's persistent DPR entry mode.

A user merely looking at Detailed DPR can therefore silently make Detailed the default for future days.

That is not acceptable.

OBJECTIVE

Restore one simple daily workflow:

Field Home
→ Start Today's Site Work
→ Guided DPR
→ Save Draft
→ Field Home shows exactly what remains incomplete
→ Complete Today's DPR
→ SAME Guided DPR draft
→ finish closing values
→ Submit.

Detailed DPR must remain available as an explicit secondary/advanced view, but viewing it must not silently reprogram the user's future default.

Equipment already recorded in Equipment & Fleet must be recognised/reused in Guided DPR rather than blindly entered twice.
