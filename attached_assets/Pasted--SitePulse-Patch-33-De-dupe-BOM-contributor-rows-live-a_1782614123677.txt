# SitePulse — Patch 33: De-dupe BOM contributor rows + live auto-refresh

Two fixes from your feedback (Plan-vs-Actual & DPR were just stale-page refreshes — Patch 33
makes that auto):

## Fix 1 — Same BOQ item repeated 4–6× in the BOM breakdown
When an item is split into multiple programme bars (reach-fronts), the BOM pushed **one
contributor row per bar**, so "[10.09] Dense Bituminous Macadam" showed 4 times, "[4.03]" 6
times, etc. This merges them into **one row per item** (summing the quantity).
File: `shared/planningEngine.ts` — three spots (materials, equipment, labour).

### 1a. Materials breakdown — FIND:
```ts
      row.breakdown.push({
        itemDescription: item.itemName || item.description,
        fullDescription: item.description,
        itemCode: item.itemCode,
        qtyPerUnit: effQtyPerUnit,
        workQty,
        lineQty,
        isAuto: m.isAuto ?? true,
      });
```
REPLACE WITH:
```ts
      {
        const bk = (item.itemCode ?? item.description) || "";
        const exB = row.breakdown.find((b: any) => ((b.itemCode ?? b.fullDescription) || "") === bk);
        if (exB) { exB.lineQty += lineQty; exB.workQty += workQty; }
        else row.breakdown.push({
          itemDescription: item.itemName || item.description,
          fullDescription: item.description,
          itemCode: item.itemCode,
          qtyPerUnit: effQtyPerUnit,
          workQty,
          lineQty,
          isAuto: m.isAuto ?? true,
        });
      }
```

## Fix 2 — Live auto-refresh on all pages (no more manual refresh)
File: `client/src/lib/queryClient.ts` — FIND:
```ts
      queryFn: getQueryFn({ on401: "throw" }),
      refetchInterval: false,
      refetchOnWindowFocus: false,
      staleTime: Infinity,
      retry: false,
```
REPLACE WITH:
```ts
      queryFn: getQueryFn({ on401: "throw" }),
      refetchInterval: false,
      refetchOnWindowFocus: true,   // refresh when you return to the tab
      refetchOnMount: true,         // refresh on every page open / navigation
      refetchOnReconnect: true,
      staleTime: 15_000,            // treat data as fresh for 15s, then auto-refetch
      retry: false,
```
This makes every page re-fetch on open, on tab focus and on reconnect — so DPR, Plan-vs-Actual,
BOM etc. stay current without a manual reload. (I avoided a constant polling interval so we don't
hammer the server; if you want true seconds-level polling on a specific live screen, tell me which
and I'll add a targeted `refetchInterval` there.)
