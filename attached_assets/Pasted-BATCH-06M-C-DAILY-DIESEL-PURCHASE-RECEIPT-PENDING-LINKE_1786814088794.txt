BATCH 06M-C — DAILY DIESEL PURCHASE
RECEIPT PENDING + LINKED MATERIAL RECEIPT + VARIANCE CONTROL

This is a focused anti-pilferage / stock-control batch.

--------------------------------------------------
OBJECTIVE
--------------------------------------------------
When Diesel is purchased through the Daily Diesel Requirement workflow:

Purchase completion must NOT automatically increase Plant Stock.

Instead, the purchase must remain visibly:
PURCHASED — RECEIPT PENDING
until an authorised Stores / Site / Equipment / Plant user records the
physical Diesel receipt through the EXISTING Material Receipt flow.

SitePulse must then show:
Purchased Qty
Received Qty
Pending Qty

and distinguish:
- Receipt Pending
- Partly Received
- Fully Received

The Material Receipt must be positively linked back to the Diesel Requirement
purchase so Purchased vs Received can be audited reliably.

Direct Site Purchase remains completely unchanged.

Expected schema change: likely ONE small additive nullable linkage field on
material_receipts. Investigate first and STOP before migration if a different
schema is needed.

--------------------------------------------------
1. CONFIRMED CURRENT ARCHITECTURE
--------------------------------------------------
Current verified behavior:

A. Daily Diesel Requirement purchase records:
   - purchased quantity
   - supplier
   - rate / amount
   - bill
   - Payment Mode
   - Paid By
   - purchased status

B. Purchase completion itself does NOT add Diesel to stock.

C. Existing Material Receipt is the correct Diesel stock-IN path.

D. Material Receipt increases the Plant Material / stockLedger balance.

E. DPR Equipment Log and Equipment & Fleet Usage with:
   dieselSource = plant_stock
   consume from that same recorded Diesel stock.

F. 06M-B now prevents Plant Stock from going negative.

G. There is currently NO stable linkage between:
   diesel_requirements
   and
   material_receipts.
   That linkage is the missing control this batch addresses.

--------------------------------------------------
2. BUSINESS CONTROL
--------------------------------------------------
Keep these facts separate:

REQUIRED
= what site requested.

PURCHASED
= what Purchaser says was bought.

RECEIVED
= what an independent receiver physically confirms.

CONSUMED
= what equipment later uses.

Do not automatically treat Purchased as Received.

Example:
Required: 600 L
Purchased: 600 L
Received: 570 L
Pending: 30 L

The 30 L must remain visibly unresolved.

--------------------------------------------------
3. RECEIPT STATUS
--------------------------------------------------
For a purchased Daily Diesel Requirement derive:

A. RECEIPT PENDING
   receivedQty = 0

B. PARTLY RECEIVED
   receivedQty > 0
   and receivedQty < purchasedQty

C. FULLY RECEIVED
   receivedQty >= purchasedQty

Do not create another manually-maintained status if this can be derived safely
from linked Material Receipts.
Prefer derived receipt state.

--------------------------------------------------
4. MATERIAL RECEIPT LINK
--------------------------------------------------
Investigate the current material_receipts schema.

Preferred minimum linkage:
material_receipts.linked_diesel_requirement_id
nullable FK/reference to diesel_requirements.id

Use a clear name consistent with current naming conventions.

This allows every Diesel Material Receipt created from a Daily Diesel Purchase
to be traced back to its purchase.

If current schema already has a generic source/reference field that can do this
safely and uniquely, reuse it instead.
Do NOT overload free-text remarks as the linkage.

--------------------------------------------------
5. SCHEMA STOP GATE
--------------------------------------------------
If one additive nullable linkage field is sufficient:
report it and proceed only if additive/safe under the current migration rules.

If more schema is required:
STOP and report before implementation.

No destructive migration.

Expected form:
ALTER TABLE material_receipts
ADD COLUMN linked_diesel_requirement_id ... NULL

Exact type/FK/index according to existing schema conventions.

Do not add stock at this stage.
Do not require the Purchaser personally to receive it.

7. PERSISTENT RECEIPT-PENDING ACTION
--------------------------------------------------

PURCHASED — RECEIPT PENDING

Do not make the action disappear.

On the Diesel Requirement detail/card provide:
[Record Material Receipt]
until fully received.

This is not a one-time toast.
It must remain an outstanding operational item.

--------------------------------------------------
8. WHO CAN RECORD RECEIPT
--------------------------------------------------
Use EXISTING permissions.
Do not invent new roles.

Allow Record Material Receipt for users who already have the relevant
Material Receipt / Plant Stock entry permission, such as authorised:
- Stores
- Site user
- Equipment / Plant
- PM/Admin
according to the Permissions Panel.

Purchaser may also record it only if their existing permissions allow Material
Receipt.
Do not grant stock-entry permission merely because someone is Purchaser.

--------------------------------------------------
9. OPEN EXISTING MATERIAL RECEIPT FORM
--------------------------------------------------
Record Material Receipt must open the EXISTING Material Receipt entry form.
Do not build a Diesel-specific receipt screen.

Prefill:
- Material = Diesel
- Supplier = Diesel purchase supplier
- suggested Qty = outstanding pending quantity
- UoM = purchase UoM / Diesel master UoM
- purchase reference / bill number where field exists
- linkedDieselRequirementId
- relevant site/plant/party context where determinable

Receiver must confirm actual Received Qty.
Do not auto-save.

--------------------------------------------------
10. RECEIVER MUST ENTER ACTUAL PHYSICAL QTY
--------------------------------------------------
Suggested Qty may equal Pending Qty.
But the receiver must be able to enter the actual physical quantity received.

Example:
Purchased: 600 L
Suggested Receipt: 600 L
Actual Received: 570 L

Save:
570 L receipt

Then show:
Purchased: 600 L
Received: 570 L
Pending: 30 L
Status: Partly Received

Do not silently force 600 L.

--------------------------------------------------
11. MULTIPLE / PARTIAL RECEIPTS
--------------------------------------------------
Allow more than one linked Material Receipt if the existing receipt system
supports multiple receipts safely.

Example:
Purchase: 600 L
Receipt 1: 400 L
Receipt 2: 170 L
Total Received: 570 L
Pending: 30 L

Each receipt remains its own stock-IN transaction.
Do not consolidate them into one fake receipt.

--------------------------------------------------
12. FULL RECEIPT
--------------------------------------------------
Once cumulative valid linked receipts >= purchased quantity:

show:
FULLY RECEIVED
Purchased: 600 L
Received: 600 L
Pending: 0 L

Disable the normal:
Record Material Receipt
action.

If over-receipt exists:
show it explicitly rather than hiding it.

Example:
Purchased 600 L
Received 620 L
Variance +20 L

Do not silently clamp Received to Purchased.

--------------------------------------------------
13. RECEIPT AGGREGATION RULE
--------------------------------------------------
Received Qty must be calculated only from valid linked Material Receipts.

Exclude according to existing receipt rules:
- cancelled
- deleted
- rejected / invalid receipt records
  if the current Material Receipt lifecycle has such states

Use the same stock-validity rule already used by Plant Stock.
Do not count free-text/unlinked Diesel receipts.

--------------------------------------------------
14. CANCEL / EDIT RECEIPT
--------------------------------------------------
If a linked Material Receipt is later:
- cancelled
- deleted
- quantity edited

the Diesel purchase Received/Pending figures must recalculate from current
valid linked receipt records.
Do not store a stale receivedQty on the Diesel requirement if it can be
derived.

Example:
Purchased 600
Received 600
Later 100 L receipt cancelled
New state:
Received 500
Pending 100
Partly Received

IMPORTANT — verified against current code: cancelling a Material Receipt
(cancelMaterialReceipt) currently only flags the record isCancelled=true; it
does NOT reverse the stock ledger/balance the way edit and delete already do.
This is a pre-existing behavior of Material Receipt generally, not something
to fix in this batch (Section 37 keeps Material Receipt stock calculation out
of scope). But because of it, after a receipt is cancelled the Diesel
purchase's recalculated "Pending" figure and the actual Plant Stock balance
can diverge — the phantom quantity from the cancelled receipt may still be
sitting in stock even though the purchase now shows it as Pending again.
Do not let this go unstated. When a linked receipt is cancelled and the
purchase reverts to Partly/Receipt-Pending, show a visible note such as:
"A previously linked receipt was cancelled. Plant Stock may not have been
automatically reversed — verify stock before recording a new receipt."
Report this explicitly in section 39(G) rather than silently assuming stock
and the derived Received figure stay in sync on cancel.

--------------------------------------------------
15. PURCHASE EDIT SAFETY
--------------------------------------------------
If Purchased Qty is edited after linked receipts already exist:
show a warning.

Example:
Existing:
Purchased 600
Received 570
User changes Purchased Qty to 500.

Do not silently hide the 70 L over-receipt.

After save derive:
Purchased 500
Received 570
Variance +70

Use current purchase edit permissions.
Do not alter linked stock receipts automatically.

--------------------------------------------------
16. DIRECT SITE PURCHASE — EXCLUDED
--------------------------------------------------
Direct Site Purchase remains exactly as it works today.

Do NOT:
- create Receipt Pending
- require Material Receipt
- link it to Daily Diesel Purchase
- alter its current IN/OUT behavior

This batch applies only to Diesel purchased through the Daily Diesel
Requirement purchase process where source is intended for Plant Stock.

--------------------------------------------------
17. EXISTING PLANT STOCK
--------------------------------------------------
Do not earmark Diesel stock by purchase.
Material Receipt adds Diesel into the common Plant Stock pool.
Equipment consumes from that common recorded balance.

The purchase-to-receipt link is for:
- audit
- completeness
- anti-pilferage
- purchased-vs-received variance

not lot-based stock reservation.

But do NOT require complex purchase matching if the current context cannot be
reliably resolved.
The core guard remains based on actual stock balance.

28. HISTORICAL PURCHASES
--------------------------------------------------

- supplier
- qty
- bill number

feature.
No automatic historical backfill in this batch.

--------------------------------------------------
29. DUPLICATE RECEIPT SAFETY
--------------------------------------------------
If a user opens Record Material Receipt twice:
do not automatically create duplicate receipt rows.
Normal Material Receipt save semantics remain.

After first save:
recalculate Pending Qty.

If fully received:
normal Record Receipt action disappears.

If partly received:
next action should suggest only the remaining Pending Qty.

--------------------------------------------------
30. UOM SAFETY
--------------------------------------------------

Note: diesel_requirements has no stored UoM column of its own (qtyPurchased is
a bare number) — only material_receipts.uom is an explicit field. Treat all
diesel_requirements quantities as Liters, matching the canonical Diesel plant
material's defaultUom, when comparing against linked receipt quantities.

Do not mix:
L
LTR
Litres
without existing normalization.

If purchase UoM differs from the canonical Diesel stock UoM and there is no
safe existing conversion:
STOP and report.
Do not invent conversions.
