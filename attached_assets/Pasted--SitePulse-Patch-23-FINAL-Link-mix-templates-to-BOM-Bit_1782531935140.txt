# SitePulse — Patch 23 (FINAL): Link mix templates to BOM + Bitumen Grade on templates

Verified against your live repo (commit `93d00f3`). Apply all blocks, then run
**`npm run db:push`** (adds the `binder_grade` column) and rebuild.

## What & why
- **Your configured mix template wasn't reaching the BOM** because the demand engine
  (`buildKeyMaterialRows`) builds numbers from the **legacy saved SDB rows** and never
  consulted the resolved template. **Section 1** makes the template-derived rows drive
  the demand (this also kills the VG-30 + VG-40 duplicate).
- **Mix templates had no bitumen-grade field.** **Section 2** adds a **Bitumen Grade**
  dropdown (VG-10 / VG-30 / VG-40 / CRMB / PMB / Emulsion) and uses it as the binder name
  in the BOM.

# Apply & verify
═══════════════════════════════════════════════════════════════════════════════
1. Apply all blocks → **`npm run db:push`** (creates `binder_grade`; type `yes` if prompted).
2. `npm run check`, rebuild/restart.
3. **Masters → edit a mix template:** set **Bitumen Grade** (e.g. VG-40 for DBM, VG-30 for BC), Save.
4. **Item recipe → Layer Config:** select the mix template — it now flows to the BOM.
5. **BOM → Materials / By Item:** bituminous items show **one** binder row in the chosen
   grade + your template's aggregate fractions + LDO. The VG-30/VG-40/Stone Dust combo is gone.

> If the saved Bitumen Grade doesn't persist, check that `storage.updateMixTemplate` /
> `createMixTemplate` write the whole `template` object (they spread `...template`, so the
> new column saves automatically once it exists).
