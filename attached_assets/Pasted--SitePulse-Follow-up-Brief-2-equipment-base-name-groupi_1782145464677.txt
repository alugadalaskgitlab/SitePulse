## FOLLOW-UP FIX 1 — Group equipment by BASE name (ignore the size/spec in brackets)
File: `shared/planningEngine.ts`

Goal: "Vibratory Roller (11T)", "Vibratory Roller (10–12T)", "Vibratory Roller (10T)" and
"VIBRATORY ROLLER" all collapse into a single **"Vibratory Roller"** row (hours summed).
Same for every machine — the part in parentheses (size/capacity) is ignored for grouping.

### 1a — add two helpers next to the existing `canonResourceKey` / `preferDisplayName`
```ts
// Equipment groups by BASE name only — the size/spec in brackets is ignored, e.g.
// "Vibratory Roller (11T)" / "(10T)" / "VIBRATORY ROLLER" → one "Vibratory Roller".
function equipmentBaseName(name: string): string {
  const base = name.split("(")[0].trim();
  return base || name.trim();
}
function canonEquipmentKey(name: string): string {
  return equipmentBaseName(name).toUpperCase().replace(/\s+/g, " ");
}
```

### 1b — replace the Equipment grouping block
Find (this is the version from the previous brief; if you never applied that, your
current block uses `const key = e.equipmentName;` — replace whichever you have):
```ts
      const key = canonResourceKey(e.equipmentName);
      if (!eqMap.has(key)) {
        eqMap.set(key, { equipmentName: e.equipmentName, count: cnt, totalHours: 0, monthlyHours: {}, breakdown: [] });
      }
      const row = eqMap.get(key)!;
      row.equipmentName = preferDisplayName(row.equipmentName, e.equipmentName);
```
Replace with:
```ts

      const display = equipmentBaseName(e.equipmentName);
      if (!eqMap.has(key)) {
        eqMap.set(key, { equipmentName: display, count: cnt, totalHours: 0, monthlyHours: {}, breakdown: [] });
      }
      const row = eqMap.get(key)!;
      row.equipmentName = preferDisplayName(row.equipmentName, display);
```

> Materials and Labour keep their full-name (case-insensitive) grouping from the previous
> brief — only **equipment** uses base-name grouping. The expand drill-down still lists

## FOLLOW-UP FIX 3 — Split the generic "Aggregate" into GSB vs WMM
File: `server/routes.ts`  (the `GET /api/boq/projects/:id/bom` handler)

Cause: granular layers (GSB sub-base and WMM macadam) both derive a single material named
**"Aggregate"**, so the BOM merges them into one 4,046 CUM line. We qualify that name with
the layer's mix type (GSB / WMM) using the item context that is already available here.

In the `expandedItems = items.map(item => { ... })` block, find the derived-materials
return (the part that maps `derived` into material rows):
```ts
          if (derived.length > 0) {
            return {
              ...item,
              materials: derived.map(dm => ({
                id: 0,
                boqItemId: item.id,
                materialName: dm.materialName,
                uom: dm.uom,
                qtyPerBoqUnit: dm.qtyPerBoqUnit,
                wastagePct: 0,
                isClientSupplied: false,
                isAuto: true as const,
                sortOrder: 0,
                createdAt: null,
                supplyType: derivedSupplyType,
              })),
              isProgrammed: barItemIds.has(item.id),
            };
          }
```
Replace it with (adds an `aggTag` and renames a bare "Aggregate"):
```ts
          if (derived.length > 0) {
            // Qualify a generic "Aggregate" with its layer's mix type so GSB and WMM
            // aggregates show as separate, clearly-labelled lines in BOM & Procurement.
            const desc = String((item as any).description ?? "");
            const aggTag =
              (lc.mixType && lc.mixType.trim()) ||
              (/wet\s*mix|\bwmm\b/i.test(desc) ? "WMM" :
               /granular\s*sub-?base|\bgsb\b/i.test(desc) ? "GSB" : null);
            return {
              ...item,
              materials: derived.map(dm => ({
                id: 0,
                boqItemId: item.id,
                materialName: (aggTag && /^aggregate$/i.test(dm.materialName.trim()))
                  ? `Aggregate (${aggTag})`
                  : dm.materialName,
                uom: dm.uom,
                qtyPerBoqUnit: dm.qtyPerBoqUnit,
                wastagePct: 0,
                isClientSupplied: false,
                isAuto: true as const,
                sortOrder: 0,
                createdAt: null,
                supplyType: derivedSupplyType,
              })),
              isProgrammed: barItemIds.has(item.id),
            };
          }
```

> The tag comes first from the layer config's mix type (deterministic); if that isn't set,
> it falls back to a light keyword check on the item description **only to choose the GSB/
> WMM label** (it does not affect any SDB norm mapping). After this, BOM Materials and the
> Procurement tab will show e.g. "Aggregate (GSB)" 1,526.7 CUM and "Aggregate (WMM)"
> 2,520 CUM as separate rows instead of one merged "Aggregate".
