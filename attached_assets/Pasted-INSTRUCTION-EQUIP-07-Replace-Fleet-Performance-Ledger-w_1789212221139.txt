BACKGROUND (confirmed by direct code review — do not re-derive)

- Diesel issued: `dieselIssued`.
- Opening/closing tank: `openingDiesel`/`openingTank` and `dieselBalanceInTank`/`closingDiesel`/`closingTank` (field names vary slightly between the two files — use whichever is authoritative per record, confirm in your report which you used).
- Expected diesel: `dieselExpected`/`expectedDiesel`.

PART 1 — NEW DIESEL CONSUMED CALCULATION (WHOLE DATE RANGE, NOT PER EVENT)
1. For each machine, within the selected date range (or, if no range is selected, from that machine's first-ever recorded usage to today — do not default to an arbitrary recent window):
   - Opening Tank = the opening tank reading from that machine's FIRST applicable usage record in the range.
   - Closing Tank = the closing tank reading from that machine's LAST applicable usage record in the range.
   - Diesel Issued = the SUM of diesel issued across every usage record in the range.
   - Diesel Consumed = Opening Tank + Diesel Issued − Closing Tank.
2. This is a new calculation — the existing per-event resolveDieselPerformance() logic (opening+issued−closing computed per individual record) should remain available for the day-by-day drill-down (Part 4) but must NOT be summed to produce the top-level Diesel Consumed figure. Compute the range-level figure directly as described above.
3. If opening or closing tank readings are missing/unreliable for the range (use the same reliability judgment already established in the earlier diesel-consumption work — describe your threshold in your report), fall back to showing Diesel Issued only, clearly labeled "Diesel Issued (measured consumption not available)" — do not label it as if it were true consumption.
4. Expected Diesel stays as currently calculated (from the equipment's consumption norm × working hours or distance, whichever this machine's norm uses) — do not change how the norm itself is calculated, only how it's displayed (Part 2).

PART 2 — NEW REPORT LAYOUT: ONE ROW PER MACHINE
Replace the current KPI cards + Machine register table + Chronological event ledger + Trend chart with a single table, one row per machine, columns exactly:
Equipment | Owned/Hired | Owner | Working Hours | Clock Duration | Diesel Issued | Opening Tank | Closing Tank | Diesel Consumed | Expected Diesel | Difference (L) | Consumption Rate

1. Equipment: machine name (reuse the existing clean equipment-label formatting already used in the Equipment Master / dropdown standardization work, if available — do not reinvent label formatting).
2. Owned/Hired: from equipment_master.ownership.
3. Owner: for owned machines show "HLC" (or "Owned" — pick one consistent word and use it everywhere); for hired machines show the vendor name already stored on the equipment master record (the same vendor name already shown in Equipment Master and equipment dropdowns) — do not require re-entering it here.
4. Working Hours: sum of meter-based working hours in range (existing `hoursWorked`/`runtimeHours`).
5. Clock Duration: sum of each day's actual start-time-to-end-time duration in range — this needs to be computed and shown as its OWN column now, not only used as a fallback when meter data is missing. Reuse `calculateEquipmentClockDuration()` for the per-day figure and sum it across the range.
6. Diesel Issued, Opening Tank, Closing Tank, Diesel Consumed: per Part 1.
7. Expected Diesel: existing calculation, shown plainly.
8. Difference (L): Diesel Consumed − Expected Diesel, in litres, with a +/− sign. Do NOT show a percentage variance anywhere on this page.
9. Consumption Rate: Diesel Consumed ÷ Working Hours (or ÷ distance/trips for odometer/trip-based machines, matching whichever unit that machine's norm already uses), shown as e.g. "8.3 L/hr" — plain, not labeled "efficiency" and not shown as a percentage.
10. Do not show "confidence," "basis," "attribution," "linked/unlinked," or any similar internal terminology anywhere on this page. If a machine's identity is still pending review, it should not appear as a normal row here at all — pending items live entirely in the Equipment Needing Identification section on Equipment Master (already built in a separate batch); this report should only ever show resolved/identified equipment.
