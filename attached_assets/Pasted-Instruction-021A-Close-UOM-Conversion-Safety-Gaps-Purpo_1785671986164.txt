Instruction 021A — Close UOM Conversion Safety Gaps

Purpose

Close two remaining safety defects in Instruction 021 before freezing Work Demand:

1. allowedUoms can still cause dimensionally different UOMs to be treated as direct factor-1 equivalents;
2. conversion profiles are selected only by fromUom and not by the required target stock/default UOM.

This is a narrow correction only.

Expected files

- shared/boqNormalise.ts
- server/routes.ts
- client/src/pages/WorkDemand.tsx
- tests for UOM compatibility

DO NOT TOUCH

- material identity/alias resolution
- Work Programme/Gantt
- horizon calculations
- demand phasing
- procurement-status logic
- material_requirements or allocations
- PI/IRN/GRN lifecycle
- conversion-profile schema
- Plant Material Master layout
- Stores or Plant workflow routing
- execution/supply responsibility

1. Do not treat all allowedUoms as factor-1 equivalents

Current behaviour permits a direct factor-1 mapping whenever the source UOM appears in allowedUoms.

Change this rule.

allowedUoms means only that the material may be transacted in those UOMs. It must not imply numerical equivalence between dimensionally different UOMs.

Direct factor 1 is permitted only when:

- canonical source UOM equals canonical target/default UOM; or
- the two labels belong to the same approved standard-equivalence group.

Examples of valid standard equivalence:

- MT ↔ Ton/Tonne
- Kg ↔ kilogram
- CUM ↔ m3/cubic metre
- CFT ↔ cubic feet
- Litre ↔ L
- Nos ↔ Number

Examples that must never use factor 1 merely because both appear in allowedUoms:

- MT ↔ CUM
- MT ↔ CFT
- CUM ↔ CFT
- loose CUM ↔ compacted CUM
- Bag ↔ MT
- Load ↔ MT/CUM
- Litre ↔ MT
- Nos ↔ metre

These require an explicit conversion profile, valid legacy factor or material-specific density.

2. Match conversion profiles by both source and target UOM

When checking an explicit profile, require:

- profile.fromUom canonically matches the BOQ/source UOM; and
- profile.toUom canonically matches the selected material’s default/stock UOM.

Do not select a profile based only on fromUom.

Example:

Material default/stock UOM: MT

Profiles:
- CUM → MT
- CUM → CFT
- CUM → Load

Only CUM → MT is applicable to the present mapping.

3. Handle multiple applicable profiles correctly

After matching both fromUom and toUom:

- exactly one active profile → use it;
- more than one active applicable profile → return MATERIAL_CONVERSION_AMBIGUOUS;
- none → continue to valid legacy/density checks, otherwise return conversion required.

Do not treat unrelated target-UOM profiles as ambiguity.

4. Apply the same rule in WorkDemand.tsx

The Resolve Material Mapping dialog currently finds a profile using only fromUom.

Update it to match:

- BOQ/source UOM; and
- selected material default/stock UOM.

The profile preview, Save button and conversion example must all use the exact same applicable profile as the server.

The server remains authoritative.

5. Planning-UOM clarification

For the current version, formally document:

- the BOM/BOQ row UOM is the planning UOM;
- the selected material defaultUom is the canonical stock/procurement UOM;
- the conversion profile converts planning UOM → stock/procurement UOM.

Do not add a new planningUom schema field in this correction unless the existing implementation cannot function without it.
