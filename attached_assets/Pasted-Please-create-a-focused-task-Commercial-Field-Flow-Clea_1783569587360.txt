# Commercial Field Flow Cleanup + Role-Based Guided UX Foundation

We need to stop adding clutter and stabilize the commercial field-user flow before further facelift.

Current problems observed in dev testing:
1. DPR progress photos are uploaded but not shown in DPR report/detail properly.
2. Site material receipt/challan photos are uploaded but not shown against the same row in Materials Received Report.
3. Site Operations screens are cluttered with Cancel / History buttons, which is confusing for field users.
4. Edit/Delete/one-time approval flow is confusing.
5. Engineer login home shows too limited actions, such as only New DPR, instead of all permitted field actions like Material Entry, IRN, PI, Equipment/Labour logs, Site Purchases, etc.
6. Road DPR and Structure DPR are still mixed/confusing in some flows; they should be separate guided flows.
7. Structure DPR should auto-populate structure name/location/chainage after selecting structure type/sub-type/structure.
8. DPR BOQ/activity dropdowns show “Other” / “Unbilled” instead of proper categories in some cases.
9. The Takkadpally-Sirur BOQ is imported and mapped, but programme activities are showing all in Month 1, which is not acceptable.
10. User Permission Centre is powerful but too cluttered and needs proper role/module/screen/action organization.
11. Session timeout options are not practical for field use; 5 minutes is too short.

Please implement in controlled phases, not as random UI changes.

==================================================
A. REMOVE FIELD SCREEN CLUTTER
==================================================

Do not show Cancel and History buttons in normal field-user screens.

For field users, keep actions simple:
- View
- Edit
- Delete only where permission and role allow
- Submit
- Upload/View Photo
- Print where applicable

Do not show Cancel button for DPR or material receipt field rows.
Do not show History button in normal field-user rows.

Audit/history can remain in backend or an Admin Audit view later, but should not clutter site engineer/operator/storekeeper screens.

Field user screens affected:
- Road DPR
- Structure DPR
- DPR History
- Material Entry / Site Material Trip
- Materials Received Report
- Site Purchases
- Site Purchases Report
- Equipment/Labour logs
- PI / IRN where applicable

==================================================
B. SIMPLIFY EDIT / DELETE / ONE-TIME APPROVAL FLOW
==================================================

Do not create separate confusing “Request Edit” buttons everywhere.

Use the same Edit button intelligently:

1. Draft / Pending Document records:
   - creator can Edit directly if they have permission
   - creator can Delete directly only if delete permission allows

2. Submitted / Finalized / Locked records:
   - if normal user clicks Edit, open reason dialog and create one-time edit request
   - request goes to eligible Sr Engineer / PM / Manager / Admin / Owner
   - same user cannot approve own request
   - approvers must respect site/project access where possible

3. Approved one-time edit:
   - same Edit button becomes active
   - applies only to that exact recordType + recordId + user
   - valid for 2 hours or until one successful save
   - consume permission only after successful save, not when Edit is clicked
   - after save, record locks again

4. Delete:
   - field staff generally should not have delete
   - Delete should be available mainly to Sr Engineer / PM / Admin / Owner based on permission
   - if delete is used, require reason and backend audit
   - do not show Cancel as substitute for Delete in field screens

5. Owner/Admin:
   - can edit/delete if permission allows
   - actions must still be audited

Important bug to fix:
EditPermissionButton should not consume one-time edit permission when the user merely clicks Edit. It must be consumed only after successful save/update.

==================================================

Photo upload is incomplete unless the uploaded photo appears in the related report row/detail.

Required:

1. DPR Photos:
   - photos uploaded during DPR progress/review must show inside DPR report/detail
   - show photo thumbnails/links against the DPR or progress item
   - do not make users search photos separately

2. Materials Received / Site Material Trip:
   - challan/DC/receipt photo uploaded in Material Entry must show in Materials Received Report
   - Photos column must show thumbnail/link against the same transaction row
   - moduleType should be site_material_trip

   - verify report row id/source mapping is correct

3. Site Purchases:
   - bill/invoice/receipt photos should show against the purchase row in report/detail

4. Equipment Maintenance / Breakdown:
   - repair photos/bills should show in equipment maintenance history/report

Test requirement:
Create an actual site material entry with challan no. and photo, save/submit it, open Materials Received Report, and confirm the same row shows the photo instead of "-".

==================================================
G. SEPARATE ROAD DPR AND STRUCTURE DPR
==================================================

Road DPR and Structure DPR should be separate tiles and separate guided flows.

Do not force Road/Structure as confusing tabs inside one generic DPR page.

Road DPR flow:
1. Select site/project/date
2. Select road reach/stretch
3. Auto-populate chainage From/To when stretch is selected
4. Select BOQ/activity
5. Enter actual quantity/details
6. Labour/equipment/materials/photos
7. Review and submit

Structure DPR flow:
1. Select site/project/date
2. Select structure type
3. Select sub-type
4. Select structure ID/name
5. Auto-populate structure name, chainage/location
6. Show relevant BOQ items for that structure first
7. Allow user to search/select other valid structure BOQ items also
8. Labour/equipment/materials/photos
9. Review and submit

Important:
Do not restrict Structure DPR only to items planned for today.
If programme is delayed or activity is from an earlier/later period, engineer must still be able to enter actual work.

Use this logic:
- Primary list: items planned for this structure and not completed
- Secondary list: all BOQ items mapped/imported for this structure
- Search fallback: all valid structure BOQ items for the project
- Show warning if item is outside current programme period, but do not block entry

Same principle for Road DPR:
- show today/current planned items first
- allow valid delayed/unplanned actual entry with warning

DPR should guide by plan, not block valid site actuals.

H. FIX BOQ / PROGRAMME / DPR LINKAGE
==================================================

Issue:
Takkadpally-Sirur BOQ is imported and mapped, but programme shows all activities in Month 1.

Required:
1. Programme generation should use:
   - BOQ item type/category
   - road reach/structure location
   - quantity
   - duration/productivity/SDB/SNL where available
   - fronts/sequence
   - structure schedule where applicable

2. Do not dump all activities into Month 1.

3. If programme cannot sequence due to missing data:
   - mark as Needs Review
   - show reason
   - do not silently create bad Month 1 programme

4. DPR dropdowns should show meaningful categories/names:
   - Road item categories: Earthwork, GSB, WMM, DBM, BC, Prime/Tack, etc.
   - Structure categories: Excavation, PCC, RCC, Reinforcement, Bearings, Joints, Drainage Spouts, Weep Holes, etc.

5. Do not show “Other” or “Unbilled” when BOQ item has valid imported/mapped category.

6. BOQ item dropdowns must show:
   - code
   - short meaningful name
   - UOM
   - full description secondary

Example:
3.02 — Wet Mix Macadam — CUM
Full BOQ description below in smaller text.
