OBJECTIVE

Fix the BOQ import so contract Bill structure is preserved, road and
structure/culvert items are classified reliably and consistently, and
structure items (starting with the pipe culvert in the ALLADURG project) can
be correctly mapped against the standard MoRTH/SNL library.

Confirmed problems in the newly imported ALLADURG project
("UPGRADATION FROM ALLADURG PWD ROAD TO PAMPAD"):

1. BOQ items are not being grouped/sorted correctly by Bill No. A "Bill"
   grouping concept already exists in the app (via category/section), and the
   display already groups by it when populated correctly — but the import
   step that detects where one Bill ends and the next begins only checks one
   specific column for the literal text "Bill No" and misses other common
   phrasings/placements, silently falling back to flat file order when it
   fails. This is why culvert items appear interleaved with road items.

2. Because of that, culvert/structure items visually appear mixed into the
   road-work sequence, though this does not automatically wrong the actual
   scheduling logic used to generate programme bars — see item 3.

3. Programme sequencing (auto-generation of bars) does classify road vs.
   structure independently, using each item's own description/category, not
   file order. However, there are TWO separate places in the code that each
   independently decide whether a BOQ item is "road" or "structure": one used
   at import time, and a different, more complete one used later at
   sequencing time. They do not always agree — the import-time check misses
   some legitimate structure wording (e.g., pipe descriptions that don't
   contain the literal word "culvert"), which can cause an item to be
   mis-tagged at import and only sometimes get corrected later. Unify these
   into one classifier so there is a single source of truth.

4. The one pipe-culvert item in this project is not mapping to a standard
   MoRTH item. This is NOT a matching-algorithm bug. The app's own internal
   library of standard MoRTH reference items currently contains exactly ONE
   pipe-culvert entry (a single diameter and class). Any BOQ pipe-culvert item
   of a different diameter or class will correctly fail to match closely
   enough, because it genuinely is a different item. The fix is to expand the
   reference library with the fuller realistic range of standard pipe-culvert
   sizes/classes, not to loosen the matching threshold or force a match to the
   single existing entry.

Required end state for this batch:

CONTRACT BOQ
→ preserve Bill hierarchy/order on import
→ classify road vs structure context correctly and consistently (one

→ map structure items (starting with pipe culverts) against an adequately
  complete standard library
→ report on the existing ALLADURG project's current (likely wrong) state,

PART 3 — ONE ROAD/STRUCTURE CLASSIFIER, NOT TWO
====================================================================

Unify the import-time road/structure classification with the classifier
already used by the sequencer, so there is a single source of truth instead
of two independently-maintained keyword lists that can disagree.

Distinguish at least:
A. LINEAR ROAD WORK -- planned by reach/chainage stretch, road productivity/
   resource logic.
B. LOCATION-BASED STRUCTURE WORK (Pipe Culvert, Slab Culvert, Box Culvert,
   Minor/Major Bridge, drain/retaining structure where applicable) -- planned
   by structure/location/chainage, must NOT be divided/sequenced as ordinary
   road length.

Do not globally classify an ambiguous generic BOQ description merely because
one word matches. Do not guess a classification the existing rules cannot
support confidently -- surface it for review instead.
