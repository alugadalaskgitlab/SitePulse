BACKGROUND (confirmed by direct code review — do not re-derive)
The existing "Owner Review Queue" and "Legacy Identity Corrections" panels on Fleet Performance (client/src/pages/EquipmentPerformanceReport.tsx) already share a single underlying mechanism: POST /api/reports/equipment-performance/logs/:id/confirm → server/storage.ts confirmEquipmentPerformanceLog. There is no merging work needed between the two existing panels; they already drive the same action.

CONFIRMED SCOPE NOTE ON SOURCES — READ BEFORE BUILDING PART 3
Tracing shared/equipmentPerformance.ts: the "pending identification" (unclassified / free-text machine name, no confirmed equipmentId) state can currently only arise from DPR-sourced equipment logs (dpr_log source, equipmentId nullable, "Other / Unlisted equipment" option in Guided DPR/Classic DPR). Plant Equipment Usage entries always require a real equipmentId selected from Equipment Master at entry time (PlantEquipmentUsage.tsx blocks submit without one) and are always emitted at "linked" confidence — there is currently no code path that produces a pending-identification row sourced from Plant Equipment Usage. Build View Source (Part 3) generically — handle "source type" as a field so future source types can be added — but implement and test it against DPR sources only, since that is the only real case in the current data model. Do not spend effort building a dedicated Plant Equipment Usage detail/view screen for this batch unless you discover a real pending row sourced from it (if you do, stop and report it before building a whole new viewer).
