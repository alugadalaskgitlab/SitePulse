BOQ Project Edit "Failed to update project" — confirmed root cause, targeted fix.

BACKGROUND / ROOT CAUSE ALREADY CONFIRMED IN CODE

The Edit BOQ Project screen cannot save ANY change right now — not just Total
Months, not just for imported projects. This affects every project.

Confirmed cause:

1. The update route (PATCH /api/boq/projects/:id) intentionally rejects any
   request body that contains a "startDate" property at all, returning:
     409 PROJECT_START_SETTING_REQUIRED
   with the message that the start date must be changed via Program Settings
   instead, so dependent schedule dates/calendar indices stay aligned. This
   guard itself is intentional and must be KEPT.

2. The Edit BOQ Project client form unconditionally includes
     startDate: form.startDate || null
   in the update payload on every save, regardless of whether the user
   actually touched the Start Date field. This means every edit — even one
   that only changes Total Months, Road Length, or Status — trips the guard
   above and is rejected.

3. The client's error handling then shows a generic "Failed to update
   project" message and swallows the specific reason returned by the server,
   which is why this looked like a mysterious/unexplained failure.

This is why Work Programme bars are not generating for the newly imported
project: Total Months could never actually be saved, because the save request
was always rejected for the unrelated startDate reason.

Do NOT investigate this as an unknown bug. Confirm the above against the
current code first (it should match), then proceed directly to the fix below.

============================================================

3. Fix the client's error handling for this save so the real server-provided
   error message (not a generic "Failed to update project") is shown to the

4. Do NOT change the PATCH /api/boq/projects/:id guard/behavior itself. It is
