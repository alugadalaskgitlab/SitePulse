# SitePulse — PATCH 7A: Clear stale BOQ recipes/mappings before re-map

Current issue:
Even after re-importing the BOQ, old/polluted recipes are still appearing in BOM & Demand.

Examples observed:

* Cement for grouting shows unrelated “Providing and fixing…” HYSD/steel source lines.
* HDPE pipe items show unrelated HYSD bar source lines.
* Materials are grouped incorrectly because old recipe rows are still attached to BOQ items.

This indicates stale recipe/mapping rows are not being fully cleared before re-import/re-map.

## Required fix

Please add a project-level cleanup before any fresh “Re-map All” or BOQ replace/re-import.

For a selected BOQ project, clear all existing auto/manual recipe and mapping rows linked to its BOQ items:

* BOQ item materials
* BOQ item equipment
* BOQ item labour
* SNL mapping fields/status on BOQ items
* stale layerConfig / auto recipe data if it was generated by previous mapping

Do not delete the BOQ items themselves unless the user is replacing the BOQ.
Do not disturb BOQ category grouping.

## 1. Add/verify project-level cleanup helper

Create or verify a helper like:

```ts
async function clearAllBoqProjectRecipesAndMappings(projectId: number) {
  const items = await storage.getBoqItems(projectId);
  const itemIds = items.map(i => i.id);

  for (const itemId of itemIds) {
    await storage.clearBoqItemRecipes(itemId);
  }

  await db
    .update(boqItems)
    .set({
      snlItemId: null,
      mappingStatus: "unmapped",
      mappingConfidence: null,
      mappedBy: null,
      mappedAt: null,
      // clear only mapping-generated layer config if applicable
      // do not touch imported BOQ categoryId/category grouping
    })
    .where(eq(boqItems.boqProjectId, projectId));
}
```

Please adjust field names to match the actual schema.

## 2. Verify `clearBoqItemRecipes(itemId)`

`clearBoqItemRecipes(itemId)` must delete all three recipe tables for that BOQ item:

```ts
boqItemMaterials
boqItemEquipment
boqItemLabour
```

It should not clear only materials.

## 3. Add a “Clear Recipes & Re-map” flow

Before running “Re-map All”, the app should first clear stale recipes/mappings for that project, then run fresh mapping.

Flow:

```text
Clear all existing BOQ item recipes/mappings for project
→ Run SNL auto-map
→ Apply recipes only for mapped/major items
→ Leave non-major/unmapped items empty
→ Refresh BOM & Demand
```

## 4. Re-import / Replace BOQ behaviour

When user chooses “replace existing BOQ” during import:

* delete old BOQ item recipes first
* delete old mapping metadata first
* then replace BOQ items
* preserve/import BOQ category grouping correctly
* do not leave old recipe rows attached to newly imported items

## 5. Verification after patch

After applying this cleanup, run it on the NH-167 project and verify:

1. BOM should not show cement for grouting with HYSD/steel item source lines.
2. HDPE pipe should not show HYSD source lines.
3. Materials should not have unrelated BOQ source rows.
4. Equipment and Labour tabs should also be cleaned.
5. Mapping count should reset correctly before re-map.
6. After Re-map All, only fresh recipes from the current BOQ/SNL mapping should appear.

## Important

Do not change:

* BOQ category/grouping display
* Work Programme bars
* Stock
* IRN
* PI
* Dashboard
* Program Settings

This patch is only to clear stale BOQ recipe/mapping pollution before fresh mapping.
