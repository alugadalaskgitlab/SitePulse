Instruction 028 — Generalise Execution Arrangements and Add Bituminous Works

Purpose

Extend the existing Execution Arrangement framework from earthwork to bituminous road works, while first correcting the earthwork-specific assumptions that currently exist inside the shared UI, execution-state derivation and demand-component mapping.

The existing arrangement system must be reused.

Do not create:

- a separate Bituminous Outsourcing module;
- a separate bituminous arrangement table;
- a parallel approval workflow;
- a second demand engine;
- a separate Bituminous Arrangements register.

Supported bituminous work in this batch:

- Prime Coat;
- Tack Coat;
- DBM;
- BC;
- SDBC;
- Bituminous Macadam;
- Seal Coat;
- Premix Carpet;
- recognised asphalt/bituminous mix supply and laying items.

Supported arrangements:

- Company In-house;
- Complete Supply and Lay;
- Finished Mix Supply Only;
- Mix Production Only;
- Production and Transport;
- Spraying Only;
- Laying and Compaction Only;
- Supply, Transport and Lay;
- Main Contractor Supplies Binder;
- Main Contractor Supplies Aggregates;
- Client Supplied;
- Partly Outsourced / Shared Responsibility;
- Not Decided.

PRELIMINARY — IMPORTANT CURRENT-CODE FACTS

The implementation must recognise these actual current conditions:

1. Work Programme arrangement controls are currently gated by isEarthworkBar.
2. earthwork_arrangements has no workCategory field.
3. components JSONB is structurally flexible, but the dialog and component arrays are hard-coded for earthwork.
4. executionState.ts uses earthwork-specific arrangement types and significant-component keys.
5. existing demand filtering partly relies on regex matching of equipment and labour names.
6. ExecutionArrangements.tsx is visually generic but still connected to earthwork-named types, endpoints and dialogs.
7. Bituminous materials, mix-template/JMF derivation and prime/tack emulsion demand already exist in the BOM engine.

Do not implement Bituminous support by only adding more keywords to isEarthworkBoqItem or by inserting bituminous keys into the current earthwork-only arrays.

DO NOT TOUCH OR REGRESS

Do not alter:

- the proven earthwork quantity exclusion behaviour;
- operational arrangement-status gating;
- overlap quantity caps;
- bar-level phasing;
- legacy arrangement fallback;
- pending revisions not affecting demand;
- immediate query invalidation;
- current Earthwork arrangement records or history;
- GSB/WMM classification and demand;
- UOM conversion;
- current JMF/mix-template calculations;
- bitumen and emulsion normalisation;
- PI/IRN/GRN;
- Stores stock;
- Plant production records;
- DPR;
- Work Programme calendar axis;
- Auto Sequence;
- LHS/RHS;
- baseline/reforecasting;
- Concrete/RMC arrangements;
- culvert/structure arrangements;
- subcontract billing;
- Cancel GRN.

- equipment/resource mappings;

- fields relevant to the category.

Minimum categories:

- earthwork
- bituminous

Do not duplicate the same arrays separately in client, server and planning engine.

PART C — SEPARATE BITUMINOUS CLASSIFICATION

- DBM;

8. Add isBituminousBoqItem

Create a separate shared classifier using:

- explicit BOQ work category/layer metadata first;
- accepted complete descriptions and abbreviations second;
- manual classification override last.

Recognise:

- Prime Coat;
- Tack Coat;
- Dense Bituminous Macadam / DBM;

- Semi-Dense Bituminous Concrete / SDBC;

- Open-Graded Premix Surfacing;
- Asphalt Concrete;
- Bituminous Mix Supply;
- Bituminous Supply and Lay;
- Emulsion Spraying.

- coat;
- mix;
- concrete;

9. Protect BC versus cement concrete

Examples:

- “Providing and laying Bituminous Concrete” → bituminous
- “BC 40 mm” under pavement/bituminous category → bituminous
- “PCC M15” → not bituminous
- “RCC M30” → not bituminous
- “Cement Concrete” → not bituminous

Add real tests for these ambiguous abbreviations.

10. Manual override

Allow PM/Admin to set:

- Bituminous Arrangement Eligible
- Not Bituminous
- Review Required

- override value;
- reason;
- user;
- timestamp.

PART G — EXPLICIT COMPONENT-TO-DEMAND MAPPING

19. Do not rely only on regex equipment-name matching

The current earthwork engine partly maps equipment and labour using regular expressions.

For bituminous support, create an explicit maintained mapping registry.

Preferred sources in order:

A. explicit resource component metadata on the BOQ rate-analysis/resource row;
B. category registry mapping by canonical equipment/material/resource key;
C. narrow backward-compatible regex fallback only for historic unmapped records.

Do not use the regex fallback as the primary design.

20. Stable bituminous resource mappings

At minimum map:

Materials:

- aggregate material rows → appropriate aggregate components;
- binder/VG bitumen → binder_bitumen;
- emulsion for spray coats → emulsion or prime_tack_material;
- filler → mineral_filler;
- additives → additives/anti_stripping_agent.

Equipment:

- HMP/hot-mix plant → hot_mix_plant / mix_production;
- loader at plant → loading_at_plant;
- transport tipper/truck → mix_transport / transport_tippers;
- mechanical sprayer → mechanical_sprayer;
- paver → paver;
- tandem roller → tandem_roller;
- PTR/pneumatic roller → pneumatic_tyre_roller;
- finish roller → finish_roller.

Labour:

- plant operator → plant_operators;
- driver → transport_drivers;
- spraying crew → spraying_crew;
- paving crew → paving_crew;
- roller operator → roller_operators;
- QC/lab staff → production_qc / field_qc / laboratory_testing.

Fuel:

- plant fuel → plant_fuel;
- tipper diesel → transport_diesel;
- sprayer fuel → sprayer_fuel;
- paving/rolling fuel → paving_diesel.

21. Earthwork compatibility

Do not rewrite the verified earthwork exclusion engine unnecessarily.

Earthwork may continue using its current mappings initially, but migrate reusable mapping infrastructure into the shared registry where safe.

All existing earthwork tests must still pass.

PART H — REUSE EXISTING BITUMINOUS BOM AND RATE ANALYSIS

22. Verify the existing recipe before filtering

The BOM engine already derives recognised bituminous:

- aggregates;
- binder;
- filler;
- mix-template/JMF materials;
- prime/tack emulsion.

Before applying an arrangement, verify that the BOQ item’s loaded recipe contains all expected resources.

Show an explicit warning when a responsibility component has no corresponding demand resource:

DEMAND_COMPONENT_MAPPING_MISSING

Example:

Arrangement assigns paver to Agency, but the BOQ rate analysis contains no paver resource.

Do not pretend paver demand was excluded when no paver demand existed in the first place.

23. Do not generate fictional resources

The arrangement system filters calculated demand.

It must not invent:

- plant hours;
- paver hours;
- roller hours;
- diesel;
- labour;

when those resources are absent from the rate analysis, productivity configuration or existing recipe.

Instead show:

“Execution responsibility recorded, but the BOQ demand recipe has no mapped Paver resource.”

24. Preserve JMF and mix-template calculation

Rate analysis/JMF remains the source of:

- aggregate proportions;
- binder percentage;
- filler/additives;
- MT/CUM/SQM conversion where already approved;
- plant/resource coefficients;
- equipment hours;
- labour;
- fuel norms.

Do not modify the JMF because one programme bar is outsourced.

PART I — DEMAND FILTERING RULES

25. Current company only

Only components assigned to the company using this SitePulse deployment generate:

- materials;
- HMP production;
- plant resources;
- equipment;
- labour;
- diesel;
- procurement action.

External-party components remain visible as physical/commercial responsibility but are excluded from Company demand.

26. Finished Mix Supply Only

When Agency supplies finished DBM/BC mix:

Exclude for that allocated bar quantity:

- aggregates;
- binder;
- filler;
- additives;
- HMP production;
- plant fuel;
- plant labour.

Retain only Company responsibilities such as:

- transport;
- paver;
- rollers;
- paving labour;
- site diesel;
- field QC.

Prevent simultaneous raw-material demand and finished-mix supply demand for the same quantity.

27. Main Contractor Supplies Binder

Retain Company/Main Contractor binder demand.

Exclude Agency-owned:

- aggregates;
- filler;
- production;
- plant fuel;
- transport;
- paving;
- compaction;
- related labour and fuel.

28. Laying Only

Retain Company:

- raw materials;
- JMF;
- HMP production;
- plant fuel;
- loading;
- transport.

Exclude Agency-owned:

- paver;
- rollers;
- site labour;
- paving/rolling diesel.

29. Prime/Tack spraying

Keep execution quantity in SQM.

Separate:

- emulsion/material responsibility;
- sprayer responsibility;
- spraying labour;
- sprayer fuel;
- surface cleaning.

Do not use emulsion MT/litres as the arrangement allocation quantity when the programme bar is in SQM.

30. Partial and shared responsibility

Shared components require an explicit:

- percentage;
- quantity;
- programme-bar allocation; or
- named component split.

Never assume 50:50.

Validate component percentages total 100%.
