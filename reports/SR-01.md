# SR-01 — DPR labels and staff links

## Changes

- Renamed the visible DPR work section and guided step to **Work done**. Internal keys, API routes, database values, test IDs, Excel output, and the Structure Works Progress heading remain unchanged.
- Updated DPR section card titles, friendly status labels, context line, Materials detail, and display casing for site, project, and people names. The optional Site activities section was not changed.
- Added nullable `users.personnel_id` and `dprs.engineer_personnel_id` links to the existing personnel list. User-to-staff links are Owner-only and unique; new DPRs use active staff, prefilling the logged-in user's linked staff member. Existing DPR engineer text is not backfilled or rewritten.
- Added Owner-only staff-link support in submitted-DPR corrections. The selected staff member must be active and the saved engineer text must match that staff record.
- Added the requested personnel role choices while retaining the existing roles.
- Added safe handling for permission-map entries missing from generated data; missing entries remain unavailable.

## Migration and startup

Migration `0055_dpr_engineer_personnel_links.sql` was applied to **both development databases**: `sitelog_dev` and the Publish-facing development database `heliumdb`. It adds only:

- `users.personnel_id` — nullable integer, FK to `personnel(id)`, with a unique partial index for non-null values.
- `dprs.engineer_personnel_id` — nullable integer, FK to `personnel(id)`, with a lookup index.

No production database was queried or changed. No user or DPR records were changed, and no DPR activities were added to real records. The restarted development app reported startup readiness `ready: true` (`2178` columns checked).

## Verification

- Focused checks: **8 test files passed, 104 tests passed**. This includes DPR section saves, Guided and detailed DPR flows, section order, user/staff linking and uniqueness, Owner-only submitted-DPR staff linking and validation, and correction history.
- `npm run build`: passed. Existing Browserslist age and large-chunk warnings remain.
- Synthetic browser fixtures only; no real user login or data edits were performed.
