Current issue:
Camera and Gallery buttons are not behaving clearly. Camera should open the phone/tablet camera where supported. Gallery should open photo library/files. Attachments should also be visible in the related report/detail row after upload.

A. Common Camera/Gallery component

Create or update one reusable component for attachment capture.

It should have two separate buttons:

1. Camera
2. Gallery / Photo Library / Files

Do not make both buttons trigger the same generic file input.

B. Camera button

Camera button should use a separate hidden file input:

<input type="file" accept="image/*" capture="environment" />

Expected:
- On mobile/tablet where supported, it should open rear camera.
- On desktop/browser where camera capture is not supported, fallback to file picker is acceptable.
- Do not break desktop usage.

C. Gallery button

Gallery button should use a separate hidden file input:

<input type="file" accept="image/*,application/pdf" />

No capture attribute.

Expected:
- On mobile/tablet, opens photo library/files depending on browser.
- On desktop, opens normal file picker.
- Allows images and PDFs.

E. Preview before save

After selecting/taking a photo:
- show thumbnail preview before save
- show file name for PDFs
- allow removing staged attachment before save

F. Display after save

Uploaded attachments must be visible in the related record/report.

Examples:
- DPR photo should show in DPR report/detail.
- Site material challan photo should show in Materials Received Report row/detail.
- Plant material receipt photo should show in receipt detail/report.
- Site purchase bill photo should show in Site Purchase report.
- Diesel/fuel bill photo should show in fuel/diesel report/detail.
- Equipment repair photo/bill should show in maintenance history/report.

G. Unsaved changes warning

The “You have unsaved changes” warning should appear only when the user has actually changed form data or staged attachments.

If the form is clean/no changes, navigating away should not show this warning.
