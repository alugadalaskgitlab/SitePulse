## Part A — The summary table must fit the page

**The fault.** In `client/src/pages/VendorPayables.tsx` the linked-vendor summary
table is set to `min-w-[1190px]` inside an `overflow-x-auto` wrapper. On a normal
laptop window the user must scroll right to reach **Total liability** — the single
most important column on the page, and the one the page was built for. The vendor
ledger table has the same fault at `min-w-[1160px]`.

**Required.**

1. Both tables must fit the available width at a 1280px window with **no
   horizontal scrolling**, without shrinking the type below readable size.
2. The **Vendor** column stays put and stays readable when the table is narrow.
   Long names wrap or truncate with the full name on hover — they do not force the
   table wider.
3. Shorten the column headers where that buys width — "Payable now", "Coming up",
   "Total liability" keep their words; "Oldest unpaid" may wrap to two lines.
4. **Total liability must be visible without scrolling**, and must remain visually
   the strongest column.
5. Where the window is genuinely too narrow (a phone), horizontal scrolling is
   acceptable, but the vendor name must remain visible while scrolling.

**Constraints.**

- Do not drop a column to make it fit. Every column stays.
- Do not change any number, any rounding or any formatting of a money figure.
- The Credit column already appears only where some vendor has a credit. Keep that
  behaviour.

## Part B — Going back returns to payables

**The fault.** Clicking a bill from the payables page or the vendor ledger opens
the Bill Detail correctly, but after viewing, editing or changing a status the back
navigation lands the user in the Vendor Bills list instead of where they came from.
They then have to find payables again from the Reports Hub.

The app already has this pattern: Reports Hub tiles pass `?returnTo=/reports/hub`
and `client/src/pages/VendorBills.tsx` already builds a `returnTo` for material
trips.

**Required.**

1. Every link from the payables page and the vendor ledger to a bill carries a
   return marker naming the exact page it came from — the payables summary, a
   vendor's ledger, or an unlinked bill's ledger — **including the date filter in
   force**, so the user returns to the same view they left.
2. The back control on Bill Detail honours that marker and returns there, **after
   viewing, after an edit and after a status change alike**.
3. Where no marker is present, behaviour is exactly as today. Nothing changes for
   a bill reached from anywhere else.

**Constraints.**

- Reuse the existing `returnTo` convention. Do not invent a second mechanism.
- Do not change what a status change does, who may make one, or the one-way
  transition rules.

## Part C — Unlinked bills on their own tab, with their total shown

**Why.** Many unlinked bills belong to one-time or short-term vendors who will
never return. Creating a vendor master for each would clutter both SitePulse and
Tally. They should stop crowding the payables page — but they must not disappear,
because an unlinked bill counts towards nobody's liability today, so an unpaid one
is invisible.

**Required.**

1. Two tabs on the payables page: **Linked vendors** (the existing summary, the
   default) and **Unlinked bills**.
2. The Unlinked bills tab carries its own totals, computed from the same functions:
   bill count, billed, paid and balance across all unlinked bills, grouped by typed
   name as now, each group still flagged unlinked.
3. **On the Linked vendors tab, the unlinked position stays in view** as one short
   line naming the count and the total balance, with a link to the tab — for
   example *"45 unlinked bills · ₹2,34,000 balance — not included in the totals
   above."* The user must never be able to read the payables page and believe
   nothing is excluded.
4. Both tabs export to Excel. Keep the existing two-sheet workbook; the unlinked
   sheet must carry the same totals as the tab.
5. Each unlinked group names the plain step to link it: Masters → Vendors → Link
   Vendors → Pending Links. **A link is never offered or made from this page.**

**Constraints.**

- **Do not change any exclusion rule.** Unlinked bills stay out of linked-vendor
  totals, exactly as now. Only their placement and their own total are being added.
- Do not create, suggest or auto-create any vendor master record.
- Do not write to any bill.
