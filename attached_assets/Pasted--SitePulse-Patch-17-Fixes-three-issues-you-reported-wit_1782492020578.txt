# SitePulse — Patch 17

Fixes three issues you reported, with exact FIND/REPLACE blocks.
**Prerequisite:** Patch 16 must already be applied (it added the
`synthLayerConfigFromWorkType` helper and the `classifyWorkType` import).

### What this patch fixes
1. **Concrete BOM never linked to the RMC mix designs / kept saying "mix design required".**
   - Your RMC module designs now take precedence **and** a deterministic
     **MoRTH/IS standard design-mix fallback** kicks in so concrete demand
     (Cement / Sand / 20mm / 10mm / Admixture) is never blank.
   - Fixed the classifier bug: `/prime\s*coat/` did **not** match "**primer** coat"
     (the extra "r"), so your two primer-coat items fell through to a generic
     "setup required". Now matched.
   - Lump-sum / count items (Toll Booth = Nos, Admin/Maintenance Building = LS/Sqm)
     and pipe-laying items **no longer** falsely demand an RMC mix design.
2. **"Setup required" rows now have a "Configure" button** that jumps straight to
   that BOQ item's Layer Config dialog.
3. **Auto-sequence wasn't splitting into reach-wise fronts** — a boolean-OR bug
   forced `fronts = 1`. Now it defaults to multiple fronts based on road length.

### B6. Fix the auto-sequence "fronts = 1" bug (THE reason no reach-wise split)

`Math.max(1, Math.floor(Number(req.body?.fronts) || 0))` is **always ≥ 1 (truthy)**,
so the `|| <multi-front default>` after it never ran — every run collapsed to a
single "Full Length" bar.

**FIND:**

```ts
      const fronts =
        Math.max(1, Math.floor(Number(req.body?.fronts) || 0)) ||
        Math.min(5, Math.max(2, Math.ceil((roadLengthKm || 24) / 12)));
```

**REPLACE WITH:**

```ts
      const requestedFronts = Math.floor(Number(req.body?.fronts) || 0);
      const fronts = requestedFronts >= 1
        ? requestedFronts
        : Math.min(5, Math.max(2, Math.ceil((roadLengthKm || 24) / 12)));
```

  useEffect(() => {
    if (!items.length) return;
    const rid = new URLSearchParams(window.location.search).get("recipeItem");
    if (!rid) return;

    if (target) {
      setRecipeItem(target);
