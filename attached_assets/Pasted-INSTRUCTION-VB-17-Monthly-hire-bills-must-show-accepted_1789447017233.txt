BACKGROUND (confirmed by direct code review — do not re-derive)
client/src/pages/VendorBills.tsx has TWO separate render blocks that both iterate over the same `hireGroups` state, gated by `isHistoricalHireEdit`:

1. The "Equipment Hire" block (~line 2426-2577, gated `isHistoricalHireEdit && ["equipment","all"].includes(billType)`) — used only when editing a pre-VB-10 historical bill. This block computes `financials = calculateEquipmentHireFinancials({...})` (~line 2470-2474) and renders a full breakdown array (~line 2565) that explicitly lists ["Gross Hire", "− Breakdown Deduction", "− HSD Recovery", "− Other Debit/Recovery", "− Advance Adjustment", "+ Other Credit", "= Taxable/Bill Amount", "+ GST", "= Invoice Total", "− TDS", "= NET PAYABLE", "Paid", "= BALANCE THIS BILL"] as distinct, separately-labeled lines.

2. The "Auto-generated monthly hire" block (~line 2579-2676, titled "Auto-generated monthly hire", gated `!isHistoricalHireEdit && hireGroups.length > 0`) — this is the block used for EVERY normal, current-day monthly-hire bill (confirmed at ~line 1724: for a fresh/non-historical bill, hire groups only auto-populate when `hireGroups.every(group => group.basis === "monthly")` — i.e. monthly-basis hire always renders through this second block, never the first). This block shows the diesel reconciliation figures (Expected/Actual/Excess/Recovery, ~line 2621-2636) and lets the preparer Accept/Edit/No-Recovery the suggested amount (`dieselRecoveryFinalAmount`), but the ONLY dollar figure shown anywhere in this block is a single line: "Generated net line: ₹{result?.netAmount}" (~line 2408/2413). There is no Gross Hire / Breakdown Deduction / HSD Recovery breakdown here at all — once "Accept Suggested" is clicked, the recovery amount is folded invisibly into that one net figure, with nothing on screen showing it was separately deducted. This is exactly the bug reported: "it is deducting directly from the hire charges" — visually true, even though shared/hireBilling.ts's calculateHireGroup() keeps `finalRecoveryAmount` mathematically separate from `deductionAmount` internally (`netAmount = grossAmount - deductionAmount - finalRecoveryAmount`) — the UI for this block simply never surfaces that breakdown.

Diesel rate for "qty × rate" display: shared/hireBilling.ts computes `suggestedRecoveryAmount = suggestedExcess * applicableRate` (~line 908-911, 946-949) but does not currently return `applicableRate` itself in the returned diesel object — only `suggestedExcess`, `rateUnavailable`, and `suggestedRecoveryAmount`.

FIX 1 — ADD A DEDUCTIONS BREAKDOWN TO THE MONTHLY-HIRE CARD
a. In the "Auto-generated monthly hire" block (~line 2579-2676), for each group, compute the same `financials = calculateEquipmentHireFinancials({...})` used in the historical block (~line 2470-2474) — reuse that function and its existing inputs (grossHire: result?.grossAmount, breakdownDeduction: result?.deductionAmount, hsdRecovery: group.dieselRecoveryFinalAmount, otherDebit/advanceAdjustment/otherCredit from group.adjustments, gstRate/tdsRate). Do not write a new calculation — call the same function the same way.
b. Replace (or add above/below) the single "Generated net line" figure with a compact breakdown showing at minimum: Gross Hire, − Breakdown Deduction (if any), − Excess Fuel Consumed (see Fix 2 for label/value), − Other Debit/Recovery/Advance Adjustment/Other Credit (only if non-zero, to keep it compact), = Net line (final). Keep this visually compact — a small stacked list or inline row, not a large new card — this is a monthly-hire summary per machine, not the full GST/TDS invoice breakdown from the historical block (GST/TDS/Invoice Total already appear elsewhere for the bill as a whole; do not duplicate them here unless they are not shown anywhere else for monthly-basis bills — if they are missing entirely for monthly bills, flag that in your report rather than guessing whether to add them here).
c. This must update live as the preparer changes Accept/Edit/No Recovery, breakdown grace days, or other adjustment fields — no save required to see it.

FIX 2 — LABEL THE DIESEL RECOVERY LINE "EXCESS FUEL CONSUMED" WITH QTY × RATE SHOWN
a. In the diesel breakdown line added by Fix 1, label it "Excess Fuel Consumed" (not "HSD Recovery") specifically in this monthly-hire card, and show it as quantity × rate, e.g. "Excess Fuel Consumed (12.4 L × ₹95.00) = ₹1,178.00" — reuse `diesel.suggestedExcess` for quantity; for rate, either (i) have shared/hireBilling.ts's diesel-reconciliation calculation also return the `applicableRate` it already computes internally (preferred — small, low-risk addition to the returned object, not a new calculation), or (ii) derive it client-side as `diesel.suggestedRecoveryAmount / diesel.suggestedExcess` when `suggestedExcess > 0` — your call on which is cleaner, but do not recompute the rate independently from raw data.
b. If the preparer uses "Edit" to override the final recovery amount, still show the original suggested qty × rate for reference alongside the edited final ₹ figure, so it's clear what was suggested vs. what was actually applied.
c. This label change (HSD Recovery → Excess Fuel Consumed) applies ONLY to this monthly-hire card's new breakdown — do not rename anything in the historical/daily-hourly block's existing "− HSD Recovery" line (~line 2565), which stays exactly as it is.
