Fix BOQ item display naming consistently across SitePulse.

BUSINESS RULE

The full imported BOQ description belongs on the BOQ / Item Review / BOQ-management screens.

Every operational screen should display the BOQ item's SHORT NAME as the primary label.

This includes DPRs, programme, reports, equipment/labour/material links, procurement references and other operational selectors.

Do not make users read the full contract description in dropdowns or normal operational screens.

PART A — AUTHORITATIVE DISPLAY NAME

Create or use one shared helper for operational BOQ item display.

Priority:

1. Use the saved BOQ short name / itemName when it exists and is non-empty.
2. If no saved short name exists, derive a concise fallback from description using the existing shortItemName logic.
3. Only fall back to the full description when neither produces a usable label.

Do not independently implement slightly different short-name logic in GuidedDpr.tsx, SiteEntry.tsx, BillItemPicker.tsx and other screens.

Use one shared implementation so the naming cannot drift.

PART B — FIX CLASSIC / DETAILED DPR

Current bug:

In SiteEntry.tsx, BOQ selection currently assigns:

updated[idx].activity = it ? it.description.toUpperCase() : "";

This causes the DPR Activity Progress row to store/display the full BOQ description.

Change this so the activity label used for normal DPR display is the operational short name.

The BOQ item ID remains the authoritative linkage.

Do not lose access to the original full description — it remains available through the linked BOQ item for detail/report/tooltips where appropriate.

PART C — BILL ITEM PICKER

BillItemPicker should show:

Primary line:

full BOQ description, truncated/tooltip/detail only.

Do not allow the full description to expand horizontally across the screen as shown in the current DPR screenshot.

The dropdown/popup must have a sensible max width and wrapping/truncation behaviour on desktop/tablet/mobile.

A user must be able to scan the item list quickly.

PART D — GUIDED DPR

Guided DPR already uses short-name logic in several places.

Move it to the same shared display helper and remove duplicated local short-name implementations.

Do not change Guided DPR business logic.
