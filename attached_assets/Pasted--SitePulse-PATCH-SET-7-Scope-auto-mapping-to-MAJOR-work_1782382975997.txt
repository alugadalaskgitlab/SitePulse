# SitePulse — PATCH SET 7: Scope auto-mapping to MAJOR work items only

**Strategy (your call):** the system should reliably auto-map only the **major,
quantity-driving** items + their materials, and **leave everything else empty** for you to
map manually. This makes the BOM trustworthy and uncluttered — no more guessing on bearings,
detonators, gelatine, sign-board geometry, HTS strand, anchorages, etc.

**Auto-mapped categories (everything else → left unmapped/empty):**
- `EARTHWORK` — borrow earth for embankment / subgrade
- `SHOULDERS_MEDIANS` — shoulders / median / junction / bus-bay filling
- `SUBBASE_BASE` — GSB / WMM and their aggregate fractions
- `BITUMINOUS` — DBM/BC aggregate fractions, bitumen, emulsion (prime/tack coat)
- `CONCRETE` — PCC/RCC cement, aggregates, admixture
- `CROSS_DRAINAGE` — culvert pipes (NP3/NP4 sizes), headwall concrete
- `MAJOR_BRIDGES` — bridge concrete / reinforcement

Non-major items are set to **unmapped** and their (old, polluted) recipes are **cleared** on
the next Re-map — giving you a clean slate.

## `server/snlAutoMapper.ts`

### 7a. Add the allow-list (put it next to the decision-threshold constants)

**FIND**
```ts
const UNIT_MISMATCH_PENALTY = 0.30; // multiply score when units differ (near-veto)
```
**REPLACE**
```ts
const UNIT_MISMATCH_PENALTY = 0.30; // multiply score when units differ (near-veto)

// Only these MAJOR, quantity-driving work categories are auto-mapped. Everything else is
// left for the user to map manually — keeps the BOM reliable and free of obscure clutter.
const MAJOR_AUTOMAP_CATEGORIES = new Set<string>([
  "EARTHWORK",
  "SHOULDERS_MEDIANS",
  "SUBBASE_BASE",
  "BITUMINOUS",
  "CONCRETE",
  "CROSS_DRAINAGE",
  "MAJOR_BRIDGES",
]);
```

### 7b. Gate the loop: skip + clear non-major items (insert at the very top of the `try`)

**FIND**

**REPLACE**
```ts

      // ── Scope guard: only auto-map MAJOR work categories ─────────────────
      // Non-major items are left for the user to map manually. We also clear any stale
      // recipe so leftover (previously mis-mapped) materials stop polluting the BOM.
      const guardCat = boqRow.workCategory ?? inferWorkCategory(boqRow.description);
```

## How it behaves after applying

| Item type | Result |
|---|---|
| Embankment / subgrade / shoulders / median (earthwork) | **Auto-mapped** + recipe |
| GSB / WMM + aggregate fractions | **Auto-mapped** + recipe |
| Bituminous (DBM/BC aggregates, bitumen, prime/tack emulsion) | **Auto-mapped** + recipe |
| PCC/RCC concrete (cement, aggregate, admixture) | **Auto-mapped** + recipe |
| Culvert pipes / headwall concrete | **Auto-mapped** + recipe |
| Bridge concrete / reinforcement | **Auto-mapped** + recipe |
| Bearings, detonators, gelatine, sign boards, studs, HTS strand, anchorages, paints… | **Unmapped / empty** — you map these manually |

> **Protecting your manual work:** once you build a recipe for a non-major item, **lock it by
> manually mapping it** (it then has a user mapping and is skipped by every future Re-map). If
> you only edit the recipe without mapping, a later Re-map will clear it again.

### On "how reliable is the quantity?" — the honest answer
For the major items, the **most reliable quantities come from your Layer Config / Mix
Template** (which you control: layer thickness, mix design %, lead/lift), not the generic SNL
norm. The SNL norm provides a sensible default; your mix/layer settings refine it. After the
Re-map, send me 2–3 major items where the **quantity looks off** and I'll trace whether it's
coming from the SNL default or the layer/mix config, and wire it to the right source.
