BACKGROUND (confirmed by direct code review — do not re-derive)
1. `server/storage.ts`'s `updateVendorBillStatus` (paid-transition branch, ~lines 17462-17480) blocks marking a bill "paid" when `billType` is `"equipment"` OR `"all"` (combined), requiring `amountPaid >= netPayableAmount`, throwing "Record the cumulative equipment hire payment before marking this bill paid." or "Record the remaining equipment hire balance before marking this bill paid." otherwise.
2. `client/src/pages/VendorBills.tsx`'s `VendorBillPaymentDetails` component (~lines 489-654) is the ONLY place `amountPaid` is ever entered or sent to the server. The flag gating it, `isEquipmentHire` (~line 508/510), checks ONLY `billType.toLowerCase() === "equipment"` — with no branch for `"all"`. Confirmed: the mutation payload (~line 521) only includes `amountPaid` `if (isEquipmentHire)`, else spreads `{}` — so for a Combined bill, `amountPaid` is never sent at all, leaving Combined-bill users with no UI path to satisfy the backend check from point 1. Same gate (`isEquipmentHire`) also hides the "Paid This Bill (cumulative ₹)" input itself (~lines 605-609) and the PAID/BALANCE badges (~lines 552-555).
3. The Bank/Account selector (~lines 591-600) is gated by the SAME `isEquipmentHire` flag (~line 591), so it's also missing for Combined bills — confirmed this is the same root cause as point 2, not a separate bug.
4. Payment Mode (~lines 561-568) and Paid By (~lines 570-577) are NOT gated by `isEquipmentHire` — they already render for all bill types. Only the cumulative-amount field, its badges, and the bank account selector are wrongly restricted.
5. `vendorBills` schema (shared/schema.ts ~2245-2285) already has everything needed: `paymentMode`, `paidBy` (payer name/"company"), `paymentAccountKey` (references the shared company-accounts list served at `GET /api/vendor-bills/company-accounts`), `paidAt` (timestamp), and `paymentRecordedBy` (the app user who clicked Mark as Paid — distinct from `paidBy`). No schema change is needed for any part of this batch.
6. Status Progress timeline: `renderStatusSteps` (VendorBills.tsx ~2460-2504) already correctly shows a timestamp and actor name under DRAFT/VERIFIED/APPROVED/PAID identically, sourced from `paidAt`/`paymentRecordedBy` for the PAID step (~2474). This already works correctly once a bill is actually paid — confirmed NOT a bug. It does not currently show the bank/account used, which is the one genuinely missing piece here. The account-name lookup already exists (`selectedAccount = accounts.find(a => a.id === bill.paymentAccountKey)`, ~line 515) and is already used to render an "ACCOUNT: {name}" badge elsewhere on the page (~line 552) — reuse this exact lookup, don't rebuild it.
