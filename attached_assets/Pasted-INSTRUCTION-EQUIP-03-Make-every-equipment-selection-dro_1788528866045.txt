BACKGROUND (confirmed by direct code review — do not re-derive)
The "Record Equipment Usage" form (client/src/pages/PlantEquipmentUsage.tsx) and other spots in the same file build equipment dropdown option labels independently, inline, at six separate locations — there is no shared helper function. Each location formats name/registration/ownership/vendor slightly differently:
- Line ~1338 (primary "Select equipment" dropdown in the "Record Equipment Usage" dialog): `{name} ({registrationNumber}) - {hrs/km} | HIRED: {vendorName} / HLC OWN`
- Line ~1451 (transfer/receiving equipment list): `{name} ({registrationNumber}) | HIRED: {vendorName || "Unknown"} / HLC OWN`
- Line ~1460: `Owner: {vendorName || "N/A"} / HLC Owned Vehicle`
- Line ~1879: `{name}{" - "+registrationNumber}{" (HIRED: vendor)"/" (HLC OWN)"}`
- Line ~2126, ~2153: further inline name/registration/ownership concatenations for other lists/table rows
None of these guard against a blank `vendorName` the way line ~1451 does (`|| "Unknown"`) — most will literally render the string "HIRED: undefined" on screen if a hired equipment record has no vendor name saved, which is a real, user-visible bug, not just inconsistent styling.
The Equipment Master list itself (client/src/pages/Plant.tsx, ~lines 4500-4520) already has a clean, correct reference format for the same data:
```
{registrationNumber} | {ownership === "hired" ? `Hired${vendorName ? ` - ${vendorName}` : ""}` : "Owned"} | {meterType label} | Norm: ...
```
This already guards against a blank vendor name (`vendorName ? ... : ""`), uses plain "Hired"/"Owned" (not "HIRED:"/"HLC OWN"), and spells out the meter type in full ("Hour Meter"/"Odometer" rather than "hrs"/"km").
