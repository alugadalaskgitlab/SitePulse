DPR CUT/FILL SUBMIT RELIABILITY + TRIP UOM CONSISTENCY
FOCUSED FIX ONLY

Implement only the focused corrections below.

Goal:
1. Prevent valid cut/fill DPRs from failing only at final submit because materialOutcome and reusableQty became inconsistent during restore/edit/recalculation.
2. Make DPR readiness detect the same cut/fill issue before final submit.
3. Verify and consistently use the existing safe receipt-UOM conversion logic across all relevant DPR views.
4. Do not redesign cut/fill business logic or material conversion rules.

--------------------------------------------------
1. ROOT CAUSE TO FIX
--------------------------------------------------

Current validation correctly requires reusableQty whenever materialOutcome is recorded.

Current intended semantics are:

- fully_reusable
  reusableQty must equal the current excavation progress quantity

- partly_reusable
  reusableQty must be > 0 and < current excavation progress quantity

- unsuitable
  reusableQty must equal 0

The current failure mode appears when a restored/edited DPR retains materialOutcome but reusableQty is missing/stale after restore or quantity recalculation.

This causes:
- activity preview/readiness may show Ready
- final submit then fails with:
  "reusableQty is required when recording material outcome"

Fix the state consistency, not the validation rule.

--------------------------------------------------
2. NORMALIZE CUT/FILL STATE AFTER RESTORE / EDIT / QUANTITY CHANGE
--------------------------------------------------

Create/reuse one shared normalization helper for excavation material outcome.

For an excavation row:

A. fully_reusable
- reusableQty must automatically equal the CURRENT progress quantity

B. unsuitable
- reusableQty must automatically equal 0

C. partly_reusable
- preserve the entered reusableQty only if still valid
- if missing or no longer valid after quantity change, mark the row incomplete and require user correction
- do not invent a partial reusable quantity

D. no materialOutcome
- reusableQty should remain null unless existing logic requires otherwise

Run this normalization where appropriate after:
- draft restore
- autosave restore
- DPR reopen
- Edit DPR hydration
- quantity recalculation
- BOQ/geometry change that changes excavation quantity
- same-as-yesterday / copy flows if they restore materialOutcome
- any other current hydration path for progress rows

Do not silently alter a partly-reusable user-entered quantity unless it is invalid.

5. PARTLY REUSABLE VALIDATION
--------------------------------------------------

If materialOutcome = partly_reusable:

Require:
0 < reusableQty < current excavation quantity

If restored value is missing or outside the valid range:
- show the row as incomplete
- highlight the reusable quantity field
- prevent final submit
- give a clear message such as:
  "Enter reusable excavation quantity between 0 and 375 CUM."

Do not convert partly_reusable into fully_reusable or unsuitable automatically.
