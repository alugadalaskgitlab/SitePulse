BACKGROUND (confirmed by direct observation of a real DPR — screen recording)
On a DPR with a JCB assigned to two BOQ activities via Work Assignment (one as the main BOQ item, "roadway excavation," one as an Additional BOQ Item / shared-time item, "embankment - excavated earth"):
- Opening the EDIT form for this equipment row correctly shows both items by name, in the "BOQ ITEM" field and the "ADDITIONAL BOQ ITEM" field, exactly as they were originally entered. This proves the underlying data (whatever ID or reference is stored) is intact and not lost.
- Viewing the SAME equipment's Work Assignment on the READ-ONLY DPR view (the page shown after saving / when reopening the DPR to view, not edit) shows "BOQ activity unavailable" in place of the activity name, for BOTH segments — once for the main item, once for the additional item. The Activity Progress section elsewhere on the same report page correctly shows both activity names ("ROADWAY EXCAVATION", "EMBANKMENT - EXCAVATED EARTH") with full quantity detail, so the item data clearly exists and is queryable — just not correctly resolved/displayed inside the Work Assignment card specifically.

This points to the read-only Work Assignment renderer using a different lookup path than either the edit form or the Activity Progress section — likely looking up the BOQ item by the wrong field/id, not handling multiple items assigned to one work-assignment segment correctly, or hitting a lookup that only works when the data is freshly loaded in the edit form's own state (not when reconstructed from what's persisted).

b. Identify exactly what the read-only Work Assignment renderer is trying to look up (what field/id it reads) and why that lookup fails for both segments in this case, while the edit form's lookup (presumably starting from the same saved data) succeeds.
c. Report the exact cause before fixing, unless it is a simple, obviously-scoped bug (e.g. reading the wrong property name, or not iterating a list of assigned items correctly) — in which case fix it and report the cause and fix together.
