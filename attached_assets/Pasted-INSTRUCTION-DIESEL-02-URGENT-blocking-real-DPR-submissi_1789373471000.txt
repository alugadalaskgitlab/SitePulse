Immediately after `</details>`, at ~line 2852, `<DprEquipmentCompact .../>` renders — a SEPARATE, ALREADY-EXISTING component (client/src/components/DprEquipmentCompact.tsx) that independently re-renders its OWN editable Opening Meter, Closing Meter/Odometer, Start, and End inputs (lines 141-144 of that file), which is why these fields visibly appear twice. This is NOT something DIESEL-01 added — DprEquipmentCompact already existed and already duplicated these fields before DIESEL-01; DIESEL-01 only made it worse by adding a second, correctly-gated tank-balance block inside the `<details>` form, on top of DprEquipmentCompact's own, ungated one.

The actual bug behind "contractor scope still shows tank balance fields": DprEquipmentCompact.tsx lines 171-176 render its own Fuel/tank-balance block — Opening Tank (L), Closing / Physical Dip (L), Diesel Issued / Added (L), and the Physical Tank Balance Confirmed checkbox — completely UNCONDITIONALLY whenever `editable && onChange` is true. It never checks `row.dieselSource` at all. This is the block visible in the screenshots showing "Diesel source: contractor" text (line 171's exact wording) with tank-balance fields still rendered below it. This is the real DIESEL-01 violation — not the correctly-gated `EquipmentTankBalanceInputs` component, but this separate, older, ungated block inside DprEquipmentCompact that DIESEL-01 never touched because we didn't know it existed.
