============================================================

The business rule is:

A machine entered through DPR or standalone Equipment Usage must produce the same
quality of operational record.

DPR already knows:
- project/site
- DPR date
- activity/task
- engineer/context

Standalone Equipment Usage may ask for location/context explicitly.

But these core fields must behave consistently:

- equipment
- operator
- task
- meter type
- opening reading
- closing reading
- start time
- end time
- working hours / km run
- diesel source
- opening diesel tank balance
- diesel issued
- closing diesel tank balance
- balance confirmed
- expected diesel
- breakdown/stoppage
- optional after-shift movement

Reuse shared calculations/helpers wherever possible.

PART 3 — CONFIRMED DPR BUG: HOURS WORKED / EXPECTED DIESEL
============================================================

Current DPR screen calculates Working Hours and Expected Diesel correctly, but
those calculated values are not reliably persisted.

Fix this in this batch.

Required:

1. On EVERY DPR equipment write path:
   - DPR create
   - DPR edit/update
   - any other path persisting DPR equipment rows

   compute and save:
   - hoursWorked / kmRun as applicable
   - expectedDiesel

2. Reuse the same meter-first / time-fallback logic already proven in standalone
   Equipment Usage.

3. Meter priority remains:
   - if valid opening/closing meter exists, use meter difference;
   - if not, use start/end time fallback where applicable.

4. Respect equipment meter type:
   - Hour Meter → operating hours
   - Odometer → kilometres
   - do NOT treat km as working hours.

5. Do not invent a new calculation implementation if an existing helper can be
   shared.

6. After save/reload, the DPR must show the same Working Hours / KM and Expected
   Diesel that were shown during entry.

7. No schema change should be needed if existing fields already exist.

IMPORTANT:
If 09:22–11:00 is 1h 38m on screen, persist using the SAME canonical numeric/unit
representation already used by Equipment Usage. Do not introduce a different
string-based storage format.
